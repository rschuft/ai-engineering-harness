## Findings for the Overseer

1. **`-mon` is deprecated in QEMU 11.1.3.** QEMU warns: `'-mon' is deprecated, use
   '-object' with 'monitor-hmp' or 'monitor-qmp' types instead`. It is accepted today,
   so this is not an option rejection, and the command line was not changed. A later
   QEMU pin may remove `-mon`; replacing it (for example with
   `-object monitor-qmp,id=…,chardev=qmp`) is a profile change for the Overseer to
   decide, and `tools/check_profile.py` would need to allow that option.
2. **`warning: Ignoring request for interrupt vector 0`.** Emitted once during machine
   setup, before any guest code ran (status `prelaunch`, empty `serial.log`). It does
   not contain `WHPX:`, so the falsification rule does not apply. Its source in QEMU is
   not established here. Inference, unverified: QEMU's WHPX APIC code warns this way
   when an MSI with vector 0 is requested. Whether it recurs at a real boot is for
   F-03.2.2 to observe.

## Defects corrected in PREREQUISITES.md

1. **The QMP one-liner printed the wrong message for `quit`.** Cause: its reader
   returned the next line, including asynchronous events, but QEMU 11.1.3 sends the
   `SHUTDOWN` event before the reply to `quit` (observed above). The one-liner would
   print the event where the procedure expects `{}`. Classification: exposed by this
   run (the procedure was written before QEMU was available). Fix: the reader skips
   messages that carry `event`. Validated against a local stand-in server that sends
   `SHUTDOWN` before the `quit` reply: the old one-liner's last line is the event, the
   corrected one's is `{'return': {}}`.
2. **The one-liner could race the launch.** Cause: `Start-Process` returns at once, and
   the one-liner connects once with no retry, so it can fail before QEMU listens on the
   QMP port. Not observed in this run (the client used here retried), so this is a
   latent defect, detected by review. Fix: a loop before the one-liner waits until the
   port listens on 127.0.0.1 or the process exits. Validated against a listener that
   binds after one second: the loop ended after it bound, while the process still ran.
