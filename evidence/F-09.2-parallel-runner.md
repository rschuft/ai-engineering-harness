## 7. The unit guard

While a `unit` test's setup (with `setUpClass` and `setUpModule`), call or teardown runs, an
audit hook raises on the profile's launch, socket and `os.chdir` events, so the operation never
happens, and the phase fails naming each event, even when the test swallows the exception.

- **On the real suites:** `test:unit` passes, 926 tests on 8 workers: no F-09.1 `unit` class
  trips the guard, and no category changed (Overseer decision 4).
- **Injected launch:** in a throwaway clone of `0c0412f`, the line
  `subprocess.run([sys.executable, '-c', 'pass'])` added as the first line of the unit test
  `test_aieh_paths.AssetRecords.test_round_trip_and_exclusive_write` (the injection F-09.1 used).
  `test:unit` there: **exit 1, `1 failed, 925 passed`**, `FAILED
  integrations/paths/tests/test_aieh_paths.py::AssetRecords::test_round_trip_and_exclusive_write`
  with `conftest.UnitGuardViolation: unit guard: subprocess.Popen in the unit test
  integrations/paths/tests/test_aieh_paths.py::AssetRecords::test_round_trip_and_exclusive_write`.
- **In `task test`, by the dev venv** (`test_pytest_conftest.GeneratedProject`, with `-n 0` and
  `-n 2`): unit tests that launch, swallow a refused launch, open a socket, change directory or
  launch in `setUpClass` each fail (the last as one `setUpClass (...)` error row); the launched
  child never wrote its marker file; a clean unit test and a launching `integration` test pass;
  an uncategorized class and `category = 'bogus'` are refused (exit 4); a run without `-B` and
  `PYTHONDONTWRITEBYTECODE=1` is refused (exit 4); the recorded outcomes equal a stdlib profile
  of a suite with a decorator skip, an expected failure, subtests, a `setUpClass` skip and a
  skipped class, and a changed profile or a deselection fails the conformance check.

## 10. Findings

Classified per the fix-forward rule.

- **Introduced by this leaf, fixed before commit:**
  - `tools_install.main` used `argv.remove(...)`; the paths suite's own source check
    (`test_c8`, which bans `remove(` among others in `tools_install.py`) failed in the first
    parallel run. Replaced by a comprehension.
  - A loop variable `name` in `tools_install` shadowed the new set name (found in review before
    any run).
  - The guard test first asserted a message wording that only the swallowed case has; the
    other cases report the `UnitGuardViolation` itself. The assertion was corrected, not the guard.
- **Introduced by this leaf, fixed forward after commit:**
  - `c72e5aa`: `--aieh-conformance PROFILE` as two arguments made pytest take the existing
    profile (outside the checkout) for a test path while finding its root directory, before the
    conftest's options exist; pyproject.toml and conftest.py were then not loaded and pytest
    exited 4. Found by the first conformance run at `d2e6009`. The `=` form is now documented,
    in the help text, the Testing section and the tests.
  - `0c0412f`: the outcome file recorded `-n auto`'s uncapped count (32) as the workers while
    `--maxprocesses 8` started 8. It now records the started workers and the reporting worker ids;
    the tests check both.
- **Exposed by this leaf:**
  - The dev venv has no PyYAML, so `test:all` skips the four `config.yml` tests that `task
    test` runs on this host (section 4). Adding PyYAML to the dev lock would add a non-pure wheel,
    which this leaf's lock may not contain; running them under pytest needs a decision (for
    example, the dev set also installing the tools lock). Not decided here.
  - `integrations/paths/README.md` still describes `tools_install.py` as `task tools:install`
    only; it was outside this leaf's paths.
  - `task` is not on this host's PATH, so no target ran under Task's own shell; the
    `owner-host:test:if-node` block was run with Git Bash.
- **Unrelated but detected:**
  - Five ignored `__pycache__` directories from 2026-11-06 and 2026-11-07 sit in the checkout
    (`tools/`, `integrations/planning/`, `integrations/store/`, `integrations/store/tests/`,
    `integrations/storecore/`): an earlier run wrote bytecode. Left in place; not this leaf's.
  - `composition/lock/README.md`'s Files table has no row for `python/tools-requirements.txt`
    (F-07.1). Not added here.
  - The host's wall time varies by a few per cent between runs (the tool suite 107 to 112 s
    here). Another application started on the host during the last campaign step
    (`hooks:verify`), after the timed serial runs.

is isolated in commit `9d8367f`, so it can be reviewed or reverted on its own. The Quick start's

because this leaf made them wrong.
