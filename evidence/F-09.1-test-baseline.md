## 2. Counting definitions

- **launches:** process launches made by the test process itself, from the audit events
  `subprocess.Popen`, `os.system`, `os.spawn`, `os.posix_spawn`, `os.exec`, `os.fork`,
  `os.forkpty`, `os.startfile`, and `_winapi.CreateProcess` when it does not come from
  `subprocess` (which raised `subprocess.Popen` already). Failed attempts count (two launches of
  a missing `no-such-backlog` are in the baseline). Processes started by a child (git's own
  helpers, a nested suite's launches, a worker's children) are not counted: the hook is in the
  test process only. All 6,877 launches of the baseline were `subprocess.Popen` events.
- **mkdtemp:** `tempfile.mkdtemp` calls, each `TemporaryDirectory` included (it calls mkdtemp).
- **sockets / chdir:** `socket.socket` objects created; `os.chdir` calls. Recorded for the unit
  guard; not budgeted.
- **tests:** tests started, as unittest's "Ran N tests" counts them. A class that skips in
  `setUpClass` runs no test; unittest reports one skip row for it, which the outcome counts
  include (gitea: 90 tests, 94 outcome rows).
- **Attribution:** the running test (with `setUp`, `tearDown`, cleanups); else the class or
  module fixture unittest is running (found from unittest's own fixture frames); else the test
  module being imported at discovery; else unattributed (0 in every suite of the baseline).
  Import-time launches are kept on a module row (only `test_verify_seed`: 3, its git probes),
  not on a class.
- **Wall:** the suite's child process wall time (interpreter start, discovery and run), each
  test's and each class fixture's time; medians of the runs.

## 5. Classification and the HEAD baseline

**Method.** Data first: any class whose tests or class fixtures launched a process, opened a
socket or changed directory in the profile is not `unit`; that rule is what F-09.2's unit guard
enforces. Among the rest, a class whose subject is a committed artifact (policy, inventory,
profile, lock, catalog, schema, recorded upstream output, a README block) is `contract`;
otherwise `unit`. Among the launching classes: `contract` when the launches only run our own
command line to check its exit codes and output, or replay a recorded upstream output;
`integration` when they drive real components (git repositories, worker processes on one store,
real shells, `icacls`, `ssh-keygen`, `tar`, a Windows job, loopback sockets); `e2e` for the
opt-in live suites (live Backlog.md/OpenSpec, live lineage, live Gitea lifecycle and
authorization), which skip without their environment variables. No class is `performance` yet
(F-09.4 adds the first). The mechanical check (`tools/test_profile.py categories`) reports
**224 classes in 34 modules, 0 uncategorized**: unit 113, contract 39, integration 61, e2e 11,
performance 0; an independent comparison of every class's effective category with the intended
mapping found 0 mismatches (inheritance included).

## 6. The budgets

`policy/test-budgets.json` = `check_test_budget.py propose` of the baseline: per category, per
suite and in total, `tests` (at least), `launches` and `mkdtemp` (at most), exact; `wall_s` the
median rounded up to 0.1 s, enforced over three runs with `tolerance` 0.3, never below
`wall_s + min_slack_s` (0.5 s), so that sub-second scopes (e2e 0.001 s, paths 1.5 s) do not fail
on timer noise. The slack floor is the one addition to the "median with 30% tolerance" rule.
Wall budgets belong to this host; `--counters-only` checks the counters anywhere. Further rules:
a profile that is not green, nondeterministic or has an uncategorized class fails; a `unit`
class or module row with a launch, socket or chdir fails (`UNIT_NOT_ISOLATED`); a suite or
category the budgets do not name fails. Counts below budget pass with a note.

**When it runs:** `task test:budget` at the acceptance of every plan leaf and at every release,
recorded with the leaf's evidence; never from a git hook (it takes three full serial runs). This
is stated in `docs/development.md` (Testing) and in `Taskfile.yml`, not in `OVERSEER_START.md`.

## 9. Findings

Classified per the fix-forward rule.

- **Introduced by this leaf, fixed before commit:** the profile aggregation called `git
  rev-parse` and `git status` from inside `build_profile`, so its unit tests launched 8
  processes. Exposed by the leaf's own unit rule in the first HEAD profile; `build_profile` is now
  pure and `run_profile` reads the revision. Also before commit: git program keys could carry a
  temporary path (`git --git-dir <path>`); git's value-taking global options are now skipped and
  a non-word subcommand is recorded as `<path>`. The baseline has no absolute path.
- **Exposed by this leaf (for F-09.3 and F-09.4, ranked):**
  - Launch origins: `integrations/planning/planning_adapter.py` 4,978 (72%; `git cat-file`
