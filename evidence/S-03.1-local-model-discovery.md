# S-03.1 / OA-12: read-only discovery of the Owner's local Ollama installation (2026-11-10)

Requested by the Owner on 2026-11-10 (verbatim in [`bootstrap-log.md`](bootstrap-log.md), Decisions):
"First perform read-only discovery of whether my existing local Ollama installation can satisfy the initial
fixed-prompt qualification. Identify the exact available model tags, the local endpoint, and which proposed
acts would become unnecessary when no provider key or external egress is needed. Present a concise
local-first option and retain the cloud-provider alternative. Do not silently select a model, start a
service, or weaken isolation."

Nothing was started, selected, pulled or changed. The `ollama` command was **not run**: on Windows its
commands start the Ollama app when no server is running, which would have started a service. Discovery read
only the program's location, the TCP table, the process list, Ollama's model manifests and the one model's
small configuration blob (no model weights were opened), and the host's memory and display adapters.

## What exists

| Item | Observed |
|---|---|
| Program | Ollama installed per-user (`<user profile>\AppData\Local\Programs\Ollama\ollama.exe`); its file carries no readable version resource |
| Server | **Not running**: no `ollama.exe` process, nothing listening on TCP 11434 |
| Endpoint, when started | `http://127.0.0.1:11434` (Ollama's default; `OLLAMA_HOST` is unset, so it binds loopback only). Not observed live |
| Model store | the default location (`OLLAMA_MODELS` unset) |
| **Model tags** | exactly one: **`gemma4-uncensored:latest`** (`registry.ollama.ai/library/gemma4-uncensored/latest`) |
| That model | GGUF, family `gemma4`, **30.7B parameters, `Q8_0`**; weights layer `sha256:682fdd418adb3138...` of 32,635,670,112 bytes (about 32.6 GB); its own system-prompt layer (2,073 bytes) and parameters layer (109 bytes); config `sha256:b5efdb5b03111d88e4e33b99b04befd26ecf60dc42623a824158386c5434a414` |
| Host | 61.6 GiB RAM; NVIDIA GeForce RTX 5090 (32 GB by its specification; Windows reports a capped figure) and AMD Radeon integrated graphics |

**Fit for the fixed-prompt qualification:** plausible, not verified. A one-word reply from a local model is
all the qualification needs. The weights (about 32.6 GB) are at or slightly above the RTX 5090's memory, so
Ollama would likely offload part of the model to system RAM; beside the execution guest (16 GiB ceiling) and
WSL this fits within 61.6 GiB but is heavy. Not known without running it: load time, whether it runs at
all with this Ollama version, the Ollama version itself.

**On the only tag, for the Owner's choice (not a recommendation):** its name marks a variant whose
behaviour tuning may differ from the base family, and it carries its own system prompt; its provenance is
not recorded here (a library-namespace name can also come from a local `ollama create`). For a fixed prompt
this does not matter; for engineering work it is a product choice. Any use would pin it by its manifest and
config digests, not by tag.

## The local-first option (decision 0015, section 2.4: "a local model server is the degenerate case")

The broker's upstream becomes `127.0.0.1:11434` instead of an internet provider. Against the acts of
[the S-03.1 request](S-03.1-owner-authorization-request.md):

| Act | With local Ollama |
|---|---|
| Choice: provider, key, spend cap | **No key and no billing**; the choice is the model tag (and its pinned digests) |
| A1 provider key in Credential Manager | **Unnecessary**: Ollama takes no key |
| A2 broker on the host (two loopback listeners) | **Still needed**: Ollama has no authentication, so the guest must never reach it directly; the broker keeps the per-attempt token, the model allowlist, the budgets and the audit |
| A3 the guest-to-host path (SSH remote forward) | **Still needed** (to the broker, never to 11434) |
| A4 the guest composition relaxations | **Still needed** |
| A5 the broker's egress to one provider origin | **Unnecessary**: no internet egress; the broker's only upstream is loopback |
| A6 the first model call (fixed prompt, no repository content) | **Still needed** |
| **New: start the local Ollama server** | **Needed**: a host service on `127.0.0.1:11434` from the existing installation, loading about 32.6 GB of weights (GPU memory and system RAM) while it runs; stopped afterwards |

**What changes for data and money:** prompts and completions never leave the host; nothing is billed.
**What stays disclosed:** Ollama is an unpinned host program outside `composition/`; whether the Ollama
desktop app makes its own outbound connections (for example update checks) is not verified, so the
qualification would start the server alone (`ollama serve`) rather than the app, and the host census
would record its connections. The broker's design is unchanged; only its upstream and A1/A5 drop out.

## The cloud-provider alternative (retained)

Unchanged from [the request](S-03.1-owner-authorization-request.md): a dedicated, provider-capped key in one
Credential Manager entry (A1), the broker's egress to one provider origin (A5), prompts and completions
leaving the host under the provider's terms, billing on that key.

## What the Owner would decide

Either option, answered per act as in the request: for local-first, the model tag (and acceptance of its
pinned digests), A2, A3, A4, A6 and the new act (start the Ollama server for the qualification); for cloud,
the request as written. Nothing is selected or started until then.
