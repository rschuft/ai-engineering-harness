## 1. What was built

`integrations/dispatch/conversation_containment.py` (README section "The containment observation (S-03.3,
slice 1)"):

- `collect container`: run inside the conversation container as its user. Every process of the container's PID
  namespace with its parent, executable, `argv0`'s last segment, the first absolute path among the next three
  arguments, the argument count, the identity and confinement fields of `/proc/<pid>/status` and the cgroup v2
  path; the listening TCP sockets (IPv4 and IPv6) with their owning pids from `/proc/<pid>/fd`; the container's
  `memory.max`, `cpu.max` and `pids.max`.
- `collect host --pid <State.Pid>`: run as the guest's root. Every host process in the PID namespace of the
  container's init, with its namespaced pids, the processes outside the namespace whose parent is inside, and the
  limits of the init's cgroup.
- `container_verdict`, `host_verdict`, `sets_verdict`: the judgement on the host (README table). The inner server
  is identified by function (the one owner of the port-8000 listener), not by path; the provider's adapter by the
  pinned image's wrapper chain (`node` running `/acp-node/bin/claude-agent-acp`, executable `/acp-node/bin/node`;
  likewise `codex-acp`); the provider's tree is the adapter and all its descendants. A new inner-server
  conversation whose `parent_conversation_id` is the observed conversation is classified as started through the
  children route (the route OpenHands' `start_child_conversation` uses), so the record separates mechanism (c)
  of the slice plan section 2.4 from the provider's own processes (mechanisms (a), (b)).

Design points, each from a source or a record, not a choice of policy:

- **Fail closed.** An unreadable status, cgroup, parent chain or adapter executable, an ambiguous inner server,
  an adapter not found, a provider process the host cannot place, or malformed input is a failed check or a
  `ContainmentError`, never a pass.
- **Every process, not only the provider's.** Inside a PID namespace every process descends from PID 1, so
  "descends from the inner server" is the meaningful check: an orphan reparented to PID 1 (a double-forked
  daemon), a process entered from outside (parent 0, as `docker exec` gives) and a lost parent chain each fail.
  The collector's own chain through the bash route is named and still judged for identity and cgroup.
- **The two views are independent in what they read.** The container view is taken from inside the boundary it
  judges; the guest-root view reads the host's `/proc` and the cgroup files of the container's cgroup and is
  compared with `docker container inspect`'s `HostConfig` (`Memory`, `NanoCpus`, `PidsLimit`) and `State.Pid`.
  Provider processes are matched across the views by namespaced pid (`NSpid`) and executable; a transient one that
  ended between the two snapshots is listed (`provider_vanished`), the adapter must be seen in both.
- **No secret is collected.** No environment, file content or socket payload is read; of the argument vector only
  `argv0`'s last segment and one absolute path are kept (a token or a URL argument is not a path).
- **Expected values** are the profile's job confinement (`jobs.process`: capabilities `0000000000000000`,
  `no_new_privs` `1`, `seccomp` `2`), the server user's uid and gid as observed by the caller, and the admitted
  caps (`expected_limits('4g', 2.0, 512)`: `memory.max` 4294967296, `cpu.max` `200000 100000`, `pids.max` 512;
  `HostConfig` 4294967296, 2000000000, 512).

## 2. Tests

`integrations/dispatch/tests/test_conversation_containment.py`, category `unit`: 72 tests, over a fake `/proc`
and cgroup tree (tini, the server's bootloader and server process owning `127.0.0.1:8000`, the Claude Code adapter,
a CLI child, a shell it started, and the collector's chain), plus one test over real files for the default file
system. Negative controls, one fact each, most asserting the exact set of failed checks (its own, plus those that
depend on it, such as the ancestry and adapter checks when no inner server is found): the adapter missing,
elsewhere, under another `argv0` or with another executable; an orphan; a sibling under the bootloader; an entered
process; a lost parent and a loop; each identity field (`Uid`, `Gid`, `Groups`, a capability, `NoNewPrivs`,
`Seccomp`, a missing field, an unreadable status); a cgroup; no cgroup anywhere; four `npx`/`npm` start shapes; a
missing, doubled or vanished inner-server owner; each limit; the init missing or with a parent; on the host side
another target, each inspected cap, the cgroup files, a member's cgroup or identity, an escaped child, a missing or
malformed namespaced pid, an adapter not seen, an executable that differs for the adapter or a CLI process, two
host processes for one inner pid; a new container, a new outer conversation, a new inner conversation of another or
no parent. Shape refusals for snapshots, expectations, limits, inspections, sets and collector output; the command
line; and a check that the file imports only the standard library (it is sent to the guest as one file).
