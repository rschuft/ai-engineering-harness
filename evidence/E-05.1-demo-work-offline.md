`core.autocrlf=false` in its own configuration.

## 5. The tests in the pinned image (prepared, not run)

`guest.py repository-tests --repo <clone> --ref main` on a running guest created with `--provision`: one disposable
conversation of the pinned fixture (no LLM, no message, no secret; the job-access-probe pattern); the branch's content,
read in process (blob bytes), sent gzipped and base64-encoded in the command's text and unpacked in the container
with `tarfile`'s data filter into `/workspace/aieh-repository-tests`; `python -m unittest discover -s tests` run there;
the conversation deleted. PASS needs the one container to be the declared one, the content unpacked, the tests' exit
0 and `OK`, and nothing left. It refuses, before anything reaches the guest, any repository whose origin is not
`aieh-d1-demo` (`REPOSITORY_NOT_AUTHORIZED`; OA-22 (i) authorizes that content only), this checkout, and anything
that is not a local branch.

The pinned image (`aieh/agent-server:1.60.1-b43ee580`, read with `guest.py image-inspect`, no guest): Python 3.13 at
`/usr/local/bin/python3.13`, with `python` and `python3` linking to it; no `/usr/bin/python*`. The command generated
for the rehearsal's content (17 files, 9292 bytes gzipped, a 13 KB command) was run under Git Bash on the host with a
local directory: it unpacked and reported `Ran 1 test`, `OK`, `rc=0`.

Network: the conversation container's network is the job environment's (default bridge, no route out of the guest:
the egress guard). The run makes no request; a namespace without a network cannot be made inside the job container
(every capability dropped). "No network in the container" is therefore realized as no egress from the guest, not as
an absent interface.
