- **Objective:** every control has a `purpose`; the ids and wording follow the blueprint's
  initial control set and minimum control record (`SEC-EXEC-01` is the blueprint's own example
  record, used for the credentials category). `RECOVER-01` is a new id: the blueprint names
  recovery obligations (`#security`, `#infrastructure-state`, `#updates`,
  `#authorization-qualification`) but no recovery control id.
- **Subject:** every kind is a lineage reference kind whose native identity the schema
  settles (`identity.settled: true`); a subject of the unsettled `release` or `catalog` kinds
  fails (`SUBJECT_UNSETTLED`).
- **Enforcement boundary:** one of the blueprint `#security` boundaries 3 to 6; the enforcing
  principal is an inventory principal that is not agent-controlled and whose trust domain is
  trusted, trusted-computing-base or contained, with inventory assets and the plan leaves that
  build it.
- **Applicability:** the profiles (additive; `baseline` always applies) and the events that
  bring the control into force; profile resolution is deterministic over the blueprint's five
  classification inputs, an unknown input selects the safer profile, and no agent downgrades a
  mandatory control.
- **Definitions, not evidence.** No control is assessed. Several "Built at" leaves are complete
  (S-01.4, S-01.2.2, P-04.2), but whether their mechanism enforces the control is evidence that
  G-01.2 links; until then each control's assessment is unknown, which never satisfies it.

## 4. Negative controls and the mutation check

- **Negative cases** (each an in-memory mutation that must fail with its code): a category
  without a control (`CATEGORY_UNCOVERED`); a missing objective (`OBJECTIVE_MISSING`); a subject
  of an unknown or unsettled kind, without scope, with an extra key or with no kinds
  (`SUBJECT_INVALID`, `SUBJECT_UNSETTLED`); missing, empty or unknown applicability, and an
  isolation control not applying always (`APPLICABILITY_MISSING`, `DANGLING_REF`,
  `APPLICABILITY_NARROW`); no enforcement, a planning boundary, no mechanism or assets, an
  unknown asset, principal or leaf (`ENFORCEMENT_MISSING`, `ENFORCEMENT_INVALID`,
  `DANGLING_REF`); an enforcer that is an agent, an agent-controlled bootstrap session, a
  principal without a domain, or an agent relabelled not agent-controlled but still in an
  untrusted domain (`ENFORCER_UNTRUSTED`); an exception on an isolation or credentials control,
  an unsettled exception without its leaf (`EXCEPTION_FORBIDDEN`, `EXCEPTION_UNSETTLED`);
  malformed profiles and a profile with no control (`PROFILE_INVALID`, `PROFILE_EMPTY`); a rule,
  exception or admission authority other than the Owner-only policy change, an admission by the
  authorization recorder, including when the inventory itself were relabelled to give it the
  policy change (`AUTHORITY`, `ADMISSION_AUTHORITY`); an admitted catalog without a verbatim
  bootstrap-log sign-off, a malformed one, or an unreadable log (`OWNER_APPROVAL`); duplicate and
  malformed ids, unknown keys, broken links and anchors, a machine path, an OSCAL claim, and a
  stale or incomplete page (`ID_DUPLICATE`, `ID_INVALID`, `SCHEMA`, `LINK_MISSING`,
  `LINK_INVALID`, `ANCHOR_MISSING`, `MACHINE_PATH`, `README_MISSING`, `README_STALE`).
- **Positive controls:** the committed catalog passes; an admitted catalog quoting a line that
  is in the bootstrap log verbatim passes.
- **Type fuzzing:** every key of the catalog, of one control, of one enforcement point, of a
  profile, of the admission and of a deferred control set to `None`, `5`, `'x'`, `[None]` and
  `{'a': 1}`: no crash; non-object catalogs give `SCHEMA` only.
- **Mutation check** (scratch script, in process: the checker's copy is mutated and the test
  module executed against it; no worker process): 196 mutants (dropping each failure code, each
  `if` forced false, each operand of each `and`/`or` in a condition dropped, each `not`
  dropped), **191 killed, 5 survived**, all equivalent: the two link-memo conditions (a cache
  only; the verdict is recomputed), a `str` guard before naming an id in the page (a non-string
  id already fails `ID_INVALID`), a `str` guard on lineage kind names (a non-string kind can
  never match a subject, which must be a string), and the start-marker guard of the generated
  block (a missing start marker still yields a block that differs from `--render`). The first
  run left 38 survivors; four redundant guards were simplified and targeted cases added.

## 5. Reconciliation and deviations

- **Location:** the blueprint places the catalog in a protected Gitea governance repository,
  which does not exist; following the development guide's planned home (`policy/`, "Policy
  (permissions, controls) ... S-01.2.1, G-01.1"), it is `policy/control-catalog.json`. Its page is
  a new `policy/control-catalog.md`; `policy/README.md` was not edited and does not link to it.
- **Minimal set:** the controls cover exactly the leaf's seven categories. The blueprint's
  initial set also names `AGENT-01`, `PLAN-01` and `REL-01`; they are listed as
  `deferred_controls` with their reasons and leaves (A-01.1/A-01.2; G-05.1; R-01.1, R-02.2.1,
  R-05.4.2). `REL-01`'s subject (a release artifact) has no settled lineage identity, so it could
  not meet the acceptance yet. **For the Overseer:** whether the catalog should absorb these three
  now.
- **Exceptions:** `prohibited` where the blueprint makes the control non-waivable (isolation,
  credentials: "Waivers must not override physical isolation or unauthorized credential access";
  `EXEC-01` "No exception allowing Owner secret access"; `SEC-EXEC-01` "exception: prohibited");
  `scoped` for `SEC-PR-01` ("request a permitted scoped exception"); `unsettled` for the other
  five, where the records do not say. Unsettled fails closed (no exception can be granted) and
  names G-06.3.1 ("Implement scoped evidence freshness and exception semantics"). **An Owner
  choice remains:** whether `SDLC-01`, `REVIEW-01`, `AUTH-01`, `ASSURE-01` and `RECOVER-01` admit
  scoped exceptions. It does not block this leaf: the fail-closed default is the blueprint's.
- **Not included:** severity per control (the blueprint gives one only for its example record),
  assessment methods and cadence (G-01.2 maps each control to its native checks), and mappings
  to external standards (the blueprint calls them alignment hypotheses; none is asserted).
- **Conftest:** not used; it is not pinned in `composition/`, and pinning a component is a
  separate change. The checker is the repository's existing standard-library pattern, as
  `#control-evidence` allows ("a small schema and JSON Schema/Conftest validation initially").
  **OSCAL:** the `oscal` block maps the fields to an OSCAL catalog export; the catalog claims
  not to be an OSCAL document, and the checker refuses any other claim.
- **Catalog admission and decision 0012:** the admission is the Owner's `op-policy-change`,
  checked against the inventory; the checker refuses an admission or authority naming the
  planned performer of `op-protected-merge` (the authorization recorder). `AUTH-01` names the
  recorder as one enforcement point because decision 0012 is about exactly that subject (the
  authorization of consequential operations); nothing extends it to catalog admission.
- **No policy service** was built; no inventory, role-token or network-matrix record changed.
