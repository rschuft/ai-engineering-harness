## 1. The tool

`image-inspect` (first run: [`S-03.3-image-adapter-check.md`](S-03.3-image-adapter-check.md), commit `3e12723`)
reported metadata, sha256 values and JSON fields only. Commit `2cfa23a` adds a text mode answered in the same second
pass that hashes the `--path` files: `--list GLOB`, `--excerpt PATH START END`, `--search GLOB REGEX` (matches over
bytes with `--context` bytes on each side; line numbers in text files), `--distinct GLOB REGEX` (distinct matched
values with counts) and, for `EXE!MODULEGLOB`, the PYZ modules of a PyInstaller executable (listed, searched after
a bounded inflate, or `--strings`: each code object's string constants and names from a walk of the marshal data,
never loaded as code). Every count is capped and a reached cap is reported; binary or oversized content is reported,
never dumped. The existing behaviour, refusals and output fields are unchanged without text requests (the existing
test file passes unchanged).

The PyInstaller part is needed because the agent server in the image is expected to be a PyInstaller executable
(`/usr/local/bin/openhands-agent-server`, the image's entrypoint) holding no `.py` source; the run checks that
expectation with two `.py` listings first in the same run.

## 4. D-1 (1): fork and sub-agents

- **ACP session fork = a new CLI process under the adapter.** The adapter advertises `sessionCapabilities.fork`
  (`A/dist/acp-agent.js` line 634) and routes `session/fork` to `unstable_forkSession` (line 6045), which calls
  `this.createSession({...}, {resume: params.sessionId, forkSession: true})` (lines 670-679). `createSession` gives the
  fork a fresh `randomUUID()` session id (lines 4029-4035) and calls the SDK's `query({prompt: input, options})`
  (line 4276) with `pathToClaudeCodeExecutable: process.env.CLAUDE_CODE_EXECUTABLE ?? (await claudeCliPath())` (line
  4189; `claudeCliPath` resolves `@anthropic-ai/claude-agent-sdk-linux-${arch}/claude`, lines 222-256). The SDK turns
  `forkSession` into the CLI argument `--fork-session` (`SDK/sdk.mjs` line 108:
  `if(this.options.forkSession)H.push("--fork-session")`), and each `query()` gets a new `ProcessTransport` whose
  `spawn()` starts the CLI (`sdk.mjs` lines 108 and 137); the SDK's own texts say the CLI is "spawned as a
  subprocess" (`SDK/extractFromBunfs.js` lines 2-3, 109-111: "ProcessTransport.isNativeBinary() decides whether to
  spawn directly or via node/bun") and document the spawn options as "command, args, cwd, env, signal"
  (`spawnClaudeCodeProcess`, `SDK/sdk.d.ts`). So each ACP session, a fork included, is its own CLI process, a child of the adapter,
  inside the adapter's process tree and the conversation container. The slice plan's section 2.4 (b) ("inside its own
  process ... UNVERIFIED") **differs**: a fork starts a new CLI process (the adapter process itself stays one).
- **Claude Code sub-agents (the `Agent` tool) report through the parent CLI's stream.** The adapter attributes
  sub-agent output by `parent_tool_use_id` on messages of the same SDK stream (`acp-agent.js` lines 143-155,
  1032-1044) and holds a turn open while "background subagents" it spawned are live (`Turn.deferredSettle`, lines
  107-112, 1247-1258, `spawnedTaskIds`). In the CLI, the sub-agent model is resolved in-process
  (`CLAUDE_CODE_SUBAGENT_MODEL` env, else the tool's `model`, else the agent's frontmatter, else `inherit` = the main
  loop model; CLI offsets 254,073,587 and 254,074,113). The source read shows no separate sub-agent executable; whether
  a sub-agent ever runs in its own OS process was **not established** by the strings read (the observation stays with
  slice 1's process tree).
- **Agent teams (separate processes) exist behind an experimental switch.** The CLI names
  `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` and a setting "How spawned teammates execute (tmux, iterm2, in-process,
  auto)"; teammates communicate by `SendMessage`. A teammate run in tmux would be a separate process in the same
  container. The gating code was not reached (inference from names only).
- **No route to an outer conversation in the adapter.** `A/dist/**` has no match for
  `openhands|/api/conversations|OH_SESSION|OH_SECRET` (0 of 21 files). The adapter talks only ACP on stdio and to the
  SDK. The CLI was not searched for OpenHands routes. As before (F-3), any process holding the inner key from its
  environment could call the **inner** server's children route; nothing read gives the adapter or CLI an outer-server
  path.
