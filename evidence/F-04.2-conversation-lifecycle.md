## 2. Design as built

### The on-demand facts (Overseer decision 2: root-only container facts)
- **Trigger.** `agent` creates `/var/lib/aieh/facts-request/conversation-facts`. The
  directory is `root:agent` `0730`: `agent` can create a file by name, but cannot list
  the directory. The root step creates it (new step `conversation-facts`, after
  `agent-server-start`) and declares it in `guest_storage` (role `facts-request`,
  `provisioned_only`), so P4's directory check covers it.
- **Units.** `aieh-conversation-facts.path` (`PathExists=` the request file,
  `TriggerLimitIntervalSec=60`, `TriggerLimitBurst=20`, enabled by the root step) starts
  `aieh-conversation-facts.service`. That is a oneshot with
  `ExecStart=/usr/bin/python3 -I /usr/local/sbin/aieh-provision conversation-facts`: no
  specifier, no variable, no argument from the request. It runs with
  `StartLimitIntervalSec=60` and `StartLimitBurst=20`, `NoNewPrivileges`,
  `ProtectSystem=strict` (writable only `/run/aieh` through `RuntimeDirectory=` and the
  request directory), `ProtectHome=read-only`, `PrivateTmp` and `IPAddressDeny=any`. It is
  ordered after `docker.service` and `aieh-agent-server.service`.
- **Input.** The reporter's first act is `os.unlink(REQUEST)`. That is the only use of the
  name: the file is never opened, and its content and metadata are never read
  (`test_the_request_is_only_removed`).
- **Container commands.** `docker ps --all --no-trunc --filter
  label=ai.openhands.runtime-owner --format json`, `docker ps --all --quiet --no-trunc`
  (a count of every container in Moby's store), and `docker container inspect <ids>`.
  Nothing else (`test_container_commands_are_ps_and_inspect_only`). Other reads are files
  and kernel state: `ss -ltnpH`, `/proc/<docker-proxy pid>/cmdline`,
  `ip_local_port_range`, the container's `resolv.conf`, `hosts` and json-file log tail
  under Moby's data root, and the stored conversations under `/srv/scratch/openhands`.
- **Output.** `/run/aieh/conversation-facts.json` (`0644`) with:
  - a `serial`, the boot id and `started_monotonic`;
  - per container: image, name, state, `Config` (user, image, labels, entrypoint, cmd,
    exposed ports, **environment names only**), the `HostConfig` fields compared, the
    `Mounts`, and the published ports and network addresses;
  - root's TCP listeners, and each `docker-proxy`'s argv;
  - per conversation directory: every file with size, mode and sha256, and each event
    file's id, kind, source and timestamp (no other content);
  - the runtime-control files by name and size (their content is encrypted key
    material);
  - the server's journal.

  Every secret value is counted and redacted before the report is written: the server's
  two, and each container's `OH_SECRET_KEY` and `OH_SESSION_API_KEYS_0`
  (`test_container_environment_is_reported_by_name_and_redacted`).
- **Freshness.** The agent-side probe notes `CLOCK_MONOTONIC`, creates the file and waits
  on inotify in `/run/aieh`. It accepts only a report whose run started after the
  request, under a 60 s ceiling. There is no fixed sleep.
- **Bound.** At most 20 runs in 60 s; past that the path unit fails closed until the next
  boot. A `conversation-smoke --restart` makes 10 requests in about 2 minutes, and an
  `inspect` makes one.

### Profile: `provisioning.agent_server.conversations` (Overseer decision 3: the mount policy)
The declared conversation container, compared exactly:
- **Image:** `.Image` is the locked image ID; `Config.Image` is the configured local tag.
- **Owner label:** the derived owner (`bdb2d2b4c2261e63b98cffe7` for the configured
  paths). Every container in Moby's store must carry it.
- **Mounts**, exactly three binds, read-write:
  - `/srv/scratch/openhands/conversations/{conversation_hex}` →
    `/var/openhands/conversations/{conversation_hex}`;
  - `/srv/scratch/openhands/persistence/runtime-data/{conversation_hex}/persistence` →
    `/var/openhands/.openhands`;
  - `/srv/scratch/openhands/persistence/runtime-data/{conversation_hex}/workspace` →
    `/workspace`.

  Every source must be under `/srv/scratch/openhands`. None may be `/run/docker.sock`,
  `/var/run/docker.sock`, `/run/containerd`, `/run/docker`, `/srv/scratch/docker`,
  `/etc/aieh`, `/var/lib/aieh`, `/etc`, `/root`, `/home`, `/proc`, `/sys`, `/dev`, `/run`
  or `/var/run`, or lie under one of them.
- **Hardening:** `Config.User` is the uid:gid of `openhands`; `CapDrop` `[ALL]` with no
  `CapAdd`; `SecurityOpt` includes `no-new-privileges`; not privileged; no device; no
  host namespace; runtime `runc`.
- **Ports:** `PortBindings` exactly `8000/tcp` on `127.0.0.1` with no fixed host port, and
  while the container runs, exactly one published binding on `127.0.0.1`.
- **Caps:** `Memory`, `NanoCpus` and `PidsLimit` equal the config's (4 GiB, 2.0 CPUs, 512).
- **Deviations** (recorded, not failed; see section 7).

`tools/check_profile.py` (`check_conversations`) validates the block: sources under
`source_root`, the forbidden list, the 1.60.1 mount destinations, cap-drop and
no-new-privileges, the 127.0.0.1 port, the three recorded deviations each carried to
later leaves, and the request directory and rate.

### `inspect` (P7 as amended, and two new provisioning checks)
Every inspect of a provisioned guest now requests the on-demand report once (probe
`conversation_facts`).
- **`profiles P7 / guest TCP listeners (Moby)`:**
  - root's boot-time report shows no Moby listener;
  - root's current report and `agent`'s `ss -ltnH` show the same set;
  - every current Moby listener passes `listener_allowance`: process `docker-proxy` or
    `dockerd`; address `127.0.0.1`; port inside `ip_local_port_range`; the published
    `8000/tcp` binding of exactly one running container that carries the owner label;
    for `docker-proxy`, its argv names that container's address and port 8000; at most
    one listener per container.
- **`profiles P7 / guest TCP listeners (Agent Server)`:** now reads root's current
  listeners; a listener inside the allowance is declared.
- **`provisioning / on-demand conversation facts`** (volatile): a report of this boot,
  the request consumed, the path unit enabled.
- **`provisioning / conversation containers`** (stable, normalised to count, owner,
  problems and deviations): every container against the declared shape.
- Without a report the four checks are UNKNOWN, never PASS.

### `conversation-smoke` (`tools/guest.py`; Task target `guest:conversation-smoke`)
On a running provisioned instance:
1. **fixture:** the pinned file (sha256 checked), its structural rules, and with
   `--openapi` its validation against the locked document;
2. **routes and server_info:** decision 0001 s2 conditions; the eight routes present in
   the server's own `/openapi.json`;
3. **facts before:** no container, no conversation directory;
4. **create:** `POST /api/conversations` with the fixture (`conversation_runtime`
   docker, the fixed id). A non-2xx is recorded as a refusal and stops the run. Then one
   owned container with no problem and one allowed listener;
5. **inspect conversation:** `GET` the conversation and its runtime;
6. **create again (idempotent):** same id, same container id, still one container;
7. **events:** `events/search` equals the event files on disk; no event of an LLM kind;
   `base_state.json` and `meta.json` stored;
8. **inspect guest (conversation running):** the full `inspect`; P3, P4, P6, P7 and
   provisioning must PASS;
9. **stop runtime:** `DELETE …/runtime`; no container, no Moby listener; the
   conversation, its runtime `missing` with `can_resume`, its events and its stored state
   unchanged;
10. **reopen:** `POST …/runtime/reprovision`; a new container with the same mounts, the
    same state, events and stored state;
11. with `--restart`, **restart guest** (graceful stop, start; the facts first, because
    the reporter is ordered after the server) and **reopen after restart**;
12. **delete:** `DELETE …/{id}`; no container, no conversation directory, no runtime
    identity or data, `GET` 404. If a run fails after the create, a cleanup `DELETE` is
    still sent.

A container image other than the locked ID, a mount outside the declared sources, or a
Moby listener outside the allowance is recorded as a stop condition and ends the run.
The API probe runs as `agent` and reads the session key from its file inside the guest.
The key is never on a command line, and any occurrence in a response is redacted and
fails the step.

## 10. Findings
1. **The release's `openapi.json` documents the local runtime only** (exposed by this
   leaf; upstream). It has no `DELETE …/runtime`, and its `GET …/runtime` and
   `POST …/runtime/reprovision` describe the in-process runtime. The Docker routes come
   from the locked wheel's `docker_runtime/routers.py` and are confirmed in the running
   server's own `/openapi.json`, which `conversation-smoke` checks before any request.
   The fixture was validated against the release document (the create schema is the
   same).
2. **A conversation with no message persists no event** (exposed; upstream behaviour,
   not a defect). The events retention check holds, but on an empty list. The retention
   proof therefore rests on the stored state (`base_state.json`, `meta.json` sha256), the
   conversation record and the listing after a restart. Making the event proof
   non-empty would need a message, for example a user message with `run: false` (no
   LLM). That is outside the fixture this leaf was authorized to send, so it is left to
   the Overseer.
3. **The inner server does not inherit the server's `enable_vscode: false` and
   `preload_tools: false`** (exposed; upstream). The conversation container starts
   VSCode on its own port 8001 and the tool preload. Both are inside the container's
   network namespace and are not published; recorded in section 7 for S-01.3.x.
4. **Residue after delete** (exposed; upstream): `runtime-control/<hex>.json.lock`
   (0 bytes) and an empty `runtime-data/.trash/`. No conversation data stays.
5. **Path boundary, builder procedure** (introduced by the builder). The first scratch
   clone used non-cone sparse patterns given on the Git Bash command line. MSYS path
   conversion rewrote `!/evidence/` to `!C:/Program Files/Git/evidence/`, so the clone
   checked out `evidence/`, including a copy of `evidence/bootstrap-log.md`. One
   `ls evidence | head -2` in the clone printed two names; neither was the protected
   file, and nothing was read. The patterns were rewritten in the clone's
   `.git/info/sparse-checkout` and `git sparse-checkout reapply` removed `evidence/`
   unread. The repository's `evidence/` was never listed or searched.
6. **Guest restart ordering** (introduced by this leaf, fixed before commit). The
   restart step queried the API before the facts. It is now reordered: the reporter's
   unit is ordered after the Agent Server's, whose start completes only at `/ready`, so
   the facts call is the completion signal. The shakedown passed with the earlier order
   too.
