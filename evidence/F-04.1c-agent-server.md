## 2. Design as built

### The root step (`profiles/seed/user-data.tmpl`), three new steps after `run`
- **`agent-server-install`.** It creates the system user `openhands`:
  `useradd --system --user-group --groups docker --home-dir /srv/scratch/openhands/home
  --no-create-home --shell /usr/sbin/nologin`, so the password is locked. It refuses if
  the user already exists. It then creates the eight declared directories under
  `/srv/scratch/openhands`, owned by `openhands`: the top at `0711`, each child at
  `0700`. It copies the binary from the verified staging copy (no links followed),
  hashes it again against the manifest to `/opt/aieh/agent-server/agent-server`
  (`root:root` `0755`), and writes `/etc/aieh/agent-server/config.json` (`root:root`
  `0644`) from the manifest.
- **`agent-server-secrets`.** It generates two values with `secrets.token_urlsafe(32)`
  (43 characters each, checked to be distinct). It writes them to
  `/etc/aieh/agent-server/secrets.env` (`root:root` `0600`, `O_EXCL`), and the session
  key alone to `/var/lib/aieh/agent-server/session.key` (`root:agent` `0440`, in a
  `root:agent` `0750` directory). It returns fingerprints only: sha256 of
  `aieh-secret-fingerprint/v1` + LF + the value.
- **`agent-server-start`.** It runs `systemctl enable --now aieh-agent-server.service`,
  which returns once the unit's `ExecStartPost` (`aieh-agent-server-ready`) sees
  `GET /ready` answer 200. It then requires root's `ss -ltnp` to show exactly
  `127.0.0.1:8000` for the process `agent-server` and no Moby listener. On a failure it
  records the start-up log, redacted.

The `facts` mode, which runs at every boot after the Agent Server, now reports:
- the unit and its hardening properties (`systemctl show`);
- the account (`getent`, `id -nG`, `passwd -S`);
- every process of the unit's cgroup: user, groups, exe, environment variable names,
  and `DOCKER_*` values;
- the binary's sha256, and the config and the secret files with their modes;
- the fingerprints;
- each data path's stat and mount;
- the engine endpoint (`docker context inspect` and `docker version` run as
  `openhands` through `setpriv`);
- the start-up log (`journalctl -b -u`).

Every secret value is counted and redacted before the agent-readable report is
written. The report also counts any occurrence of either value in RESULT.json, the
config, the manifest, the session-key file (for `OH_SECRET_KEY`) and cloud-init's logs.

### The unit (`aieh-agent-server.service`)
- `User=openhands`, `EnvironmentFile=/etc/aieh/agent-server/secrets.env`.
- `Environment=`:
  - `OPENHANDS_AGENT_SERVER_CONFIG_PATH=/etc/aieh/agent-server/config.json`;
  - `OH_PERSISTENCE_DIR=/srv/scratch/openhands/persistence`;
  - `HOME=/srv/scratch/openhands/home`;
  - `TMPDIR=/srv/scratch/openhands/tmp`;
  - `PATH` and `LANG`.
- `ExecStart=/opt/aieh/agent-server/agent-server --host 127.0.0.1 --port 8000`, with
  `ExecStartPost` the readiness wait (0.5 s poll of `/ready`, 280 s ceiling,
  `TimeoutStartSec=300`). `Restart=on-failure`.
- Conditional on the provisioning manifest, the installed binary and the secrets file.
  It is enabled only by a successful root step.
- **Hardening and why** (`provisioning.agent_server.service.hardening` in the profile):
  - **Set:** `NoNewPrivileges`, empty `CapabilityBoundingSet` and
    `AmbientCapabilities`, `ProtectSystem=strict` with
    `ReadWritePaths=/srv/scratch/openhands`, `ProtectHome`, `PrivateTmp`,
    `PrivateDevices`, `ProtectKernelTunables`, `ProtectKernelModules`,
    `ProtectKernelLogs`, `ProtectControlGroups`, `ProtectClock`, `ProtectHostname`,
    `ProtectProc=invisible`, `RestrictSUIDSGID`, `RestrictRealtime`,
    `RestrictNamespaces`, `LockPersonality`, `SystemCallArchitectures=native`,
    `SystemCallFilter=@system-service`, `RestrictAddressFamilies=AF_UNIX AF_INET
    AF_INET6 AF_NETLINK`, `IPAddressDeny=any` with `IPAddressAllow=localhost`, and
    `UMask=0077`.
  - **Why they fit:** dockerd (root, outside the unit) creates the containers, so the
    server needs no capability, namespace, device or SUID binary. A read-only mount
    does not stop `connect()` to `/run/docker.sock` (observed: the start-up
    `docker ps` succeeded).
  - **Not set:** `MemoryDenyWriteExecute` (the PyInstaller CPython is not qualified
    under it), `PrivateNetwork` (the guest must reach the listener) and `PrivateUsers`
    (it would hide the docker group).

### Deviation from the brief
The brief allowed "a `root:openhands 0640` env file or `LoadCredential`". The file is
`root:root` `0600` instead. systemd reads `EnvironmentFile=` as root before it drops to
`openhands`, so no non-root account needs the file, and it is strictly tighter. The
process environment (`/proc/<pid>/environ`) is readable only by `openhands` and root.

### Host side (`tools/guest.py`)
- `create --provision` adds the manifest's `agent_server` section: the binary's name and
  sha256, the config, the home, the directories and the listener. It holds no secret.
- `provision` additionally checks the start step's listener. It then fetches
  `/var/lib/aieh/agent-server/session.key` by SFTP as `agent` into
  `<instance>\agent-server\session.key`, refuses if that file already exists, and
  compares its fingerprint with the one the root step published. The record says only
  `fetched` and `fingerprint_matches`.
- `inspect` adds three groups of checks:
  - **P5:** secret custody, secret values in records, and key fingerprints
    (per-instance).
  - **P7:** the Agent Server listener.
  - **`provisioning (F-04.1)`:** binary; version (`/server_info`); runtime selection
    (decision 0001 s2); service; config; engine endpoint; conversation image; data
    paths; session-key enforcement; and the start-up log.

  The guest probe runs as `agent`. It reads the session key from its file inside a
  Python probe, never on a command line, and prints only its fingerprint. It queries
  `/alive`, `/server_info` and `/api/conversations/count` with the key, without it and
  with a wrong one. It `open()`s the secret file and the service's
  `/proc/<pid>/environ` without reading them.

  On the host, the instance directory (every file except the guest disks), this
  inspect's observations and the P5 collection are searched. The session key is
  searched for as a literal. `OH_SECRET_KEY` is found by fingerprinting every
  43-character window of every token run, so the host never holds it.
- Every new check is classified in `CHECK_CLASSES`. The fingerprints are per-instance,
  the start-up log is volatile, and the secret search is stable after normalising away
  the count of scanned files.

## 13. Notes for F-04.2
- **Every Docker conversation is published on the guest's loopback.** It is created
  with `-p 127.0.0.1::8000` (`registry.py` `_build_container`), so dockerd (or
  `docker-proxy`) will hold a `127.0.0.1:<ephemeral>` TCP listener while a conversation
  container runs.
  - That breaks the current P7 checks: "no TCP listener of dockerd, containerd or
    docker-proxy" (Moby) and "only base-image listeners" (Agent Server).
  - F-04.2 needs a declared, bounded allowance for it, by the contract owner, before
    its inspect can pass with a running conversation.
- **The containment findings of decision 0001 s3 are confirmed at the 1.60.1 source.**
  - `ConversationContainerOptions` memory and CPUs from a create request "replace the
    server's limit and [are] not capped by it". The fixture sends none.
  - `--add-host host.docker.internal:host-gateway` is always added.
  - There is no `--network none`.
- **Containers run as the server's uid**, which is `openhands` (999), with `--cap-drop
  ALL`, `--security-opt no-new-privileges` and `--ulimit core=0`. Their env carries a
  per-conversation `OH_SECRET_KEY` and session key (not the server's), visible to anyone
  with docker access (`openhands` and root only).
- **The browser.** `conversation_image_has_browser` is unset, and the local tag is not
  the stock repository, so the server treats the image as browser-less. The fixture
  also sends `browser: false`.
- **Data paths.** Conversation data will appear under
  `/srv/scratch/openhands/persistence/runtime-data/<id>` and
  `/srv/scratch/openhands/conversations/<id>`. The runtime creates them at `0700`.
- **The session key** is at `<instance>\agent-server\session.key`, but the Agent Server
  API has no host forward (deferred). F-04.2 can call the API over `exec` as `agent`,
  as inspect does here.
- **The fixture** is `profiles/strong-windows-qemu-whpx/agent-server/conversation-create.json`.
  Validate it again with `--openapi` before sending it.
