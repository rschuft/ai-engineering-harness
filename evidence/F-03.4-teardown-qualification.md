## 1. What was built (commits `8803d24`, `b5ff695`)

- **`tools/guest.py smoke`** and Task `guest:smoke`. The steps run in this order, and
  the first failure skips the rest, destroys the instance and still takes the final
  inventory:
  1. preflight;
  2. inventory "before create";
  3. create, with a canary set planted;
  4. inspect A;
  5. graceful stop;
  6. start;
  7. inspect B, compared with A in mode `start`;
  8. forced stop;
  9. inventory "before recreate";
  10. recreate;
  11. inventory "after recreate";
  12. inspect C, compared with A in mode `recreate`;
  13. destroy;
  14. destroy again (`absent`);
  15. inventory "after destroy".

  The four inventories are compared in pairs, and the first with the last. The verdict
  carries a P10 block with the formal test F-03.4.
- **`compare_inspect`.** Each of the 74 checks of an ordinary inspect record is in
  `CHECK_CLASSES` with its class and an optional named normalisation (68 stable, 4
  per-instance, 2 volatile). 17 record-level facts are in `INSPECT_FACTS` (10 stable,
  4 per-instance, 3 volatile).
  - Every check's verdict must be equal in both records.
  - A stable field's declared and observed values must be equal.
  - A per-instance field must be equal across a start and different across a recreate.
  - An unclassified check fails the comparison. A test pins the table to the checks
    that `evaluate` emits.
- **Inventory** (`inventory`, `diff_inventory`). No traversal of any Owner folder, and
  the state directory itself is never listed. The sources are:
  - **the checkout:** `git rev-parse HEAD`, `git status --porcelain=v2
    --untracked-files=no`, and the sha256 of `git ls-files -s`, with git under no
    global configuration;
  - **the state directory's shared content:** the pinned image (sha256, size, mtime);
    the provider prefix `providers/qemu/msys2-ucrt64-11.1.3-1` (file count, bytes, a
    digest of every file's path, size and mtime, and the sha256 of both pinned binaries
    and the firmware). `downloads\` is never touched;
  - **every other entry of `instances\`.** Each file gets its type, mode, Windows
    attributes, mtime, size and sha256. For a *running* sibling, its `root.qcow2`,
    `scratch.qcow2`, `serial.log` and `stderr.log` are recorded as present only (its
    own QEMU writes them), and its QMP status and pid are recorded;
  - **the `--durable` roots** named by the operator, recorded the same way.

## 6. XSAVE: the detector and the preflight finding

**Observed.**
- **Preflight `host-xsaves`.** `WHvGetCapability` returned:
  - `WHvCapabilityCodeHypervisorPresent`: 1;
  - `ProcessorVendor`: 0 (AMD);
  - code `0x1003`: `0x41ffffdf`;
  - code `0x1004`: 4,299,890,847 (a clock frequency in Hz).

  The last value fixes `0x1003` as `ProcessorXsaveFeatures`. Decoded with the
  `WHV_PROCESSOR_XSAVE_FEATURES` layout, the 24 named bits that have a
  `/proc/cpuinfo` flag are exactly the guest's flags:
  - present: xsave, xsaveopt, avx, avx2, fma, avx512f/dq/cd/bw/vl, **xsavec**,
    **xsaves**, avx512_bitalg, avx512ifma, avx512vbmi, avx512_vbmi2, avx512_vnni, gfni,
    vaes, avx512_vpopcntdq, vpclmulqdq, avx512_bf16, avx512_vp2intersect, avx_vnni;
  - absent in both: mpx, fp16, AMX.

  Preflight reported `ok: XSAVES offered by the hypervisor (AMD, xsave features
  0x41ffffdf)`.
- **Detector.** The sources were:
  - `serial.log (host side)`: kernel messages present;
  - `guest dmesg (as agent)`: unavailable. The probe printed `dmesg unreadable`,
    `dmesg_restrict=1`.

  All 10 inspects (9 smoke inspects and the sibling's) reported:
  - `[    0.76…] x86/fpu: misordered xstate at 1408`, labelled `misordered-xstate`
    (LIMITATION);
  - `x86/fpu: Enabled xstate features 0x8e7, context size is 2448 bytes, using
    'compacted' format.`;
  - no `XSAVE consistency problem` and no `XSAVE disabled`.

**Inference.**
- `XsaveSupervisorSupport` is what the hypervisor offers its partitions, so it is the
  XSAVES that a WHPX guest can see. On a host without it, the upstream report predicts
  the panic, and `preflight` now refuses that host. This was not observed on such a
  host.
- The compacted format implies that the guest kernel uses XSAVES.
- Extended-state correctness under load remains unqualified.
