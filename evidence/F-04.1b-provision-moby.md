## 1. Design as built

### Seed (`profiles/seed/user-data.tmpl`, re-pinned in both profiles)
- A third placeholder, `{{provision_manifest}}`, is written base64 into
  `/etc/aieh/provision.json` (root `0600`). `tools/nocloud_seed.py` accepts only one ASCII
  JSON object of schema `ai-engineering-harness/profiles/provision-manifest/v1`, LF only,
  at most 64 KiB; without a manifest the value is empty.
- The template always writes `/usr/local/sbin/aieh-provision` (Python 3, standard library,
  root `0755`), `aieh-provision.path` (`PathExists=/srv/scratch/agent/provision/READY`),
  `aieh-provision.service` (oneshot, journal and console, `TimeoutStartSec=3600`) and
  `aieh-docker-facts.service` (oneshot at every boot after `docker.service`).
- **Ordinary guests are unaffected:** the manifest is empty; both provisioning units and
  the facts unit carry `ConditionFileNotEmpty=/etc/aieh/provision.json`; `runcmd` creates
  `/var/lib/aieh/provision` and enables the trigger only under `[ -s manifest ]`; the
  facts unit is enabled only by a successful root step. The unit tests show an ordinary
  seed with `content: ""`; the passing ordinary-observation tests are unchanged.
- **Single use:** the service has `ConditionPathExists=!…/RESULT.json`; the script refuses
  when the result or the staging directory exists; in every outcome it disables and stops
  the trigger, deletes its unit file and reloads systemd.

### The root step (in order; `RESULT.json` is written last, by a rename)
`copy` (from the agent-owned upload directory into `/var/lib/aieh/provision-staging`, root
`0700`: `O_NOFOLLOW`, regular files only, only the manifest's names, sizes bounded) →
`verify` (sha256 of every staged copy against the seeded manifest) → `daemon-json` →
`sysctl` → `apt-install` (`apt-get install -y --no-install-recommends ./<5 .deb>` from the
staging directory; then `dpkg-query` versions against the manifest) → `containerd-config`
→ `docker-ready` (`systemctl start docker`, server version, no Moby TCP listener) →
`docker-load` → `image-id` → `tag` → `run` → `facts` → `cleanup` (staging and upload
removed with `shutil.rmtree`, which does not follow links) → trigger disabled → `RESULT.json`
(`/var/lib/aieh/provision/RESULT.json`, root `0644`, agent-readable; on failure it names
the step and keeps the staging directory and the upload).

The brief listed RESULT before cleanup and disabling; it is written last so that its
presence means the whole step finished and so that it records the cleanup and the
trigger state.

### Host side (`tools/guest.py`)
- `create --provision`: re-verifies the stage (`verify_staged`, about 1.7 s) and builds the
  manifest from the committed lock and `staged.json`: 5 `.deb`, `agent-server.tar` and the
  release binary (7 files, 1,476,711,620 bytes; the index files stay on the host), the
  locked config digest, the archive's tag, the local tag
  `aieh/agent-server:1.60.1-b43ee580`, and the declared `daemon.json`, sysctl drop-in and
  containerd config. The launch record keeps the manifest digest.
- `provision`: refuses unless the instance was made with `--provision`, the stage still
  gives the seeded manifest, the trigger is `active`, and neither the upload, the staging
  directory nor a result exists; checks `provisioning.upload` (8 files, 1.5 GiB, roles);
  one `sftp -b` batch (`mkdir`, 7 `put`); size and `sha256sum` of each file in the guest;
  `READY` with `set -C`; then one SSH session waits on an inotify event in
  `/var/lib/aieh/provision/` (wakes every 10 s only to see a failed unit; ceiling
  `root_step.timeout_s` = 3600 s); fetches `RESULT.json` by SFTP into
  `<instance>\provision\` and checks it.
- `inspect` of a provisioned instance: P6 `guest Moby sockets`, `agent cannot reach Moby`;
  P7 `guest TCP listeners (Moby)`; P8 `agent not in group docker`; and an entry
  `provisioning (F-04.1)` (not a contract property): root step result, facts of this
  boot, server version, daemon (root dir, driver, runtime, security options, daemon.json,
  containerd config, sysctl drop-in, `docker0` `disable_ipv6`), image, containers,
  modules, upload and staging removed, root step disabled. Root-only facts come from
  `/run/aieh/docker-facts.json`, written by root at each boot and read as `agent`.

**Design choice to note (the boot-time facts unit).** `agent` cannot query the daemon,
and there is no root exec. Required inspect facts (server version, `docker info`, the
image after a restart) need root. `aieh-docker-facts.service` is a root report written at
each boot with no input from the guest user; it is the only persistent root unit added.
The alternative was provision-time facts only, which cannot show that Moby comes back
after a restart.

## 7. Findings

1. **containerd's CRI listener** (exposed by this slice; Debian's packaged default).
   Fixed forward in `e34d495`: declared `provisioning.moby.containerd_config`, replaced
   after the install only while it is the packaged file (a conffile cannot be written
   before dpkg without a prompt or a `--force` option), containerd and docker restarted,
   and the root step refuses any Moby TCP listener. Observed in run 2: no Moby listener.
   The Overseer may prefer another mechanism (for example a systemd drop-in); this one
   keeps the package's own unit.
2. **IPv6 link-local on `docker0`** (exposed by this slice). Fixed forward: declared
   sysctl drop-in `/etc/sysctl.d/90-aieh-moby.conf` (`docker0` and `veth*`
   `disable_ipv6 = 1`), written before the install and applied by udev's systemd-sysctl
   rule. Observed in run 2: `disable_ipv6 = 1`, no address after the run and at rest.
3. **`stat %m` as agent** (introduced by this slice). Fixed: `findmnt --target`.
4. **P6 rule for undeclared sockets** (introduced by this slice). Fixed: "not writable by
   others"; the contract text says so.
5. **Compare classes** (introduced by this slice). `/run/docker/libnetwork/<id>.sock`
   gets a new id at every daemon start, and `veth` is loaded only after a container ran.
   Fixed in the commit with this file: a normaliser for the socket id, and the module
   check is volatile (its verdict, overlay loaded, must stay equal).
6. **Serial log** (unrelated but detected; known): QEMU truncates `serial.log` at each
   launch, so run 2's root-step console lines were lost at its restart. Run 1's are kept
   in the builder's scratch; `RESULT.json` is the durable record.
7. **The release binary** is uploaded and verified but not installed (slice (c)); the
   root step deletes it with the upload.
