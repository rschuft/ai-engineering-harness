## 1. The catalogue

[`security/containment-cases.json`](../security/containment-cases.json), schema
`ai-engineering-harness/security/containment-cases/v1`, version `1`, rendered in
[`security/README.md`](../security/README.md#containment-cases-s-021). Placement: `security/`,
beside the inventory whose asset, credential and finding ids the cases reference; the catalogue
describes the job environment that every profile's conversation containers share rather than one
profile's configuration, and the profile-tied paths are cross-checked against the profile by
`profile_value` instead of being stored under `profiles/`.

Each case carries `id`, `category`, `kind` (denial, hardening, deviation or permitted), `name`,
`principal` (an inventory principal, the user it runs as, and whether it is a root attempt),
`attempt` (the exact operation), `probe` (a containment-probe operation or a reused primitive's
extractor), `expected` (outcome classes and the rule in words), `enforcement` (locations with
references), `assets`, `positive_control`, `verdict_rule`, `carried` (findings), `status`
(`executable` for every case here), `depends_on` (the snapshot keys recorded with it),
`requires` and, for a deviation, `compensated_by`.

## 2. The checker

[`tools/check_containment_cases.py`](../tools/check_containment_cases.py) (`task
security:containment-check`), 33 offline tests in
`tools/tests/test_check_containment_cases.py`. It fails when:

1. a category has no denial case, or a key, kind, status, category, enforcement location,
   snapshot key or requirement is unknown;
2. a probe names no enforcement location, a location names no reference, or a reference does not
   resolve (profiles P-id, network-matrix edge, inventory asset, credential or finding); a case
   names no protected asset; its principal, assets or carried findings do not exist;
3. a probe names no positive control, or the control is not an existing, executable permitted
   case; a permitted case names a control;
4. expected outcomes are empty, a denial, hardening or deviation case expects a success outcome,
   a permitted case expects anything else, or a deviation names no compensating case;
5. a probe names an unknown source, operation or extractor, or misses an argument;
6. an attempt is not provably non-destructive: an operation outside the closed set; a
   write-class operation given a path (its paths are the runner's scratch); a deny-listed command
   (`rm`, `kill`, `mount`, `chmod`, `reboot` and the like) or anything but the allowlisted fixed
   commands and read-only engine subcommands; a TCP connect beyond `127.0.0.1`; an off-host
   target outside the S-01.4 sweeps; the route-present sweep without `requires:
   egress-falsification`;
7. a path tied to the profile (`profile_value`) differs from the profile's value;
8. a mutation names no denial case or a non-permitted operation, or a category has no mutation;
9. a machine path appears, or the README block differs from `--render`.

Wrongly typed values give named failures, never exceptions (type fuzzing in the tests). Every
failure code is exercised by a test.

## 3. The runner

`tools/guest.py containment-probe --profile … --state-dir … --name … [--sensitivity]
[--token-fingerprint L=sha256:H] [--out FILE]` (`task guest:containment-probe`):

1. loads the catalogue and refuses it unless its checker passes (nothing touches the guest);
2. takes a runtime-configuration snapshot (before);
3. runs `admission-probe` and then `job-access-probe` **unchanged** (with the catalogue's eight
   Gitea fingerprints plus any given) and keeps their full records; a stop condition in either
   stops the run before the next primitive;
4. creates two further disposable conversations of the pinned fixture
   (`a0221b00-…-0c01`, `…-0c02`) and records each container's normalized `docker inspect` digest;
5. plants a generated canary file in each job's own `/workspace/.aieh-probe` and reads its mount
   table (the first controls);
6. runs every containment-probe case in each job as its default user, one execution per distinct
   operation, peer ids and canary names filled in at run time; the script and its spec travel
   zlib-compressed and base64 (no secret on a command line; the operator API's SSH argument fits
   Windows' 32 KiB cap);
7. with `--sensitivity`, runs the mutations in the first job;
8. removes the probe scratch, deletes both conversations and checks that none remains;
9. takes the snapshot again (after), then classifies every case.

**Per case** the record holds the attempt, the principal, every observation (per container, per
address or per target, with the reused primitive's detail), the classification, the positive
control and its verdict, compensating verdicts for a deviation, the verdict and reason, the
carried findings, and the snapshot parts it depends on.

**Verdicts** (`containment_verdict`): a success outcome of a denial is a FAIL and a stop condition;
a hardening or deviation case that observes a success is a FAIL; otherwise a case whose control did
not pass is UNKNOWN, never PASS; a case with no observation is a FAIL (never skipped); an outcome
outside the expected set is a FAIL; a deviation is PASS only while every compensating case passes.
A permitted control is PASS only on its expected success. The run is PASS only when every case
passed, no step failed and (with `--sensitivity`) every mutation was classified a success; FAIL
when anything failed; UNKNOWN when only UNKNOWN cases remain.

**Snapshot** (`snapshots.before` and `.after`, and per case the keys it names): the container
guard's IPv4 and IPv6 per-rule counters and log count; the egress guard's counters and log count;
`daemon.json` (sha256 and no-new-privileges, icc, hosts), `SecurityOptions`, the guard unit and the
key check; the pins: the launch record's git revision and profile sha256, the profile's current
sha256, the `launch`, `network` and `host_shares` digests, every boot input's sha256, the
provisioning manifest, lock, image ID and Agent Server binary digests, the falsification flag, the
route inventory, fixture and catalogue sha256 and the catalogue version; and the jobs' normalized
`docker inspect` digests (the image, user, AppArmor profile, the declared HostConfig values, binds
with the conversation id replaced and the published port's host address).

## 12. Defects

All introduced by this leaf and fixed forward before the commit `dc5018a`; none remained at the
evidence run:
1. **Control `ctl-access-write-scratch` saw ENOENT** (shakedown): the scratch directory was created
   only by write operations, after the control ran. Fixed: the container script creates it first.
2. **Control `ctl-unshare-noop` saw EPERM** (shakedown): Moby's seccomp filters `unshare` for every
   flag value, so `unshare(0)` cannot be a control. Fixed: the control is a forked child that exits
   0 through the same plumbing (`ctl-fork-plumbing`), and `unshare(0)` became a denial case
   (`priv-unshare-none`) that attributes the refusal to seccomp.
3. **The container command exceeded the operator API's argument cap** (offline measurement before
   any run: 33 KB against Windows' 32 KiB): the script and spec now travel zlib-compressed; a test
   bounds every containment command below 24 KiB.
4. **A synthetic Windows profile path in a checker test** was refused by the
   publication gate at the first commit attempt; the test now uses the gate's placeholder account
   name. The gate was not bypassed.
5. **Test fakes** gave both conversations the same canary name and Moby file roots (their ids share
   a prefix); fixed in the fakes before any run.
