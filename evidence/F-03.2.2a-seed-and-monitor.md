## 2. Seed generator

`tools/nocloud_seed.py`, in `tools/` beside the other profile tooling
(`check_profile.py`, `msys2_lock.py`). Standard library only; run with `python -I -B`.

- **Spec item 1.** Imports only the standard library. It writes only
  `<instance_dir>/seed.iso.partial` (opened `xb`, fsynced) and renames that to
  `seed.iso`. It refuses when the instance directory is missing or either file exists,
  so it never creates directories and never overwrites.
- **Item 2.** It reads `boot_inputs.seed.templates` from the profile, hashes each
  template, and refuses on a mismatch. It also refuses a template that has CR bytes or
  is not UTF-8.
- **Item 3.** Each template must carry exactly its placeholders (user-data
  `agent_ssh_public_key` and `scratch_device`; meta-data `instance_id` and
  `instance_name`; network-config none). An unknown or missing placeholder, or a
  leftover `{{`/`}}`, is refused. The key must be one `ssh-ed25519 <base64> [comment]`
  line whose blob decodes to the type string plus a 32-byte key. The comment is
  optional, one token of `[A-Za-z0-9._@+=-]`, and options are not allowed. The
  instance name follows the profile's `instance_name_pattern`. The instance id must be
  `<name>-<canonical lowercase UUID>`; when it is not given, a random one is generated.
  The scratch device must be a `/dev/...` path.
- **Item 4.** The image is ISO 9660 with a Joliet SVD (`%/E`, UCS-2 level 3).
  - Volume ids: primary `CIDATA`, Joliet `cidata`.
  - Root files: Joliet `meta-data`, `network-config` and `user-data`; primary
    `META_DAT.;1`, `NETWORK_.;1` and `USER_DAT.;1`. Both trees share the file extents.
  - Geometry: 2048-byte blocks; the descriptors are PVD (16), SVD (17) and terminator
    (18), with no boot record (El Torito); directory records have no system-use area
    (no Rock Ridge).
  - Fixed values: creation and modification dates are `1970010100000000` with offset
    0; expiration and effective dates are unset; every directory-record date is
    1970-01-01 00:00:00; every text field is blank.
  - Layout: fixed file order, and no padding after the last file block.
- **Item 5.** It prints one JSON object with `sha256`, `size_bytes`, `instance_id`, and
  the per-template and per-rendered-file sha256.

**Tests** (`tools/tests/test_nocloud_seed.py`, 27, all pass). They cover:
- determinism: two in-process runs give identical bytes, and the CLI in a separate
  process gives the same digest;
- a pinned digest for a fixed input;
- a different key gives a different digest, and so does a different instance id;
- refusals:
  - a tampered template (checked against its pin);
  - an unknown placeholder, a leftover delimiter, a placeholder in network-config and
    a missing placeholder (each tamper re-pinned in a temporary copy of `profiles/`,
    so that the placeholder rule, not the pin, is what refuses);
  - 12 malformed keys: empty, RSA, two lines, an options prefix, bad base64, a short
    blob, a blob of another type, a comment with a space, a comment with `: `, a
    private-key header, non-ASCII, and more than 4 KiB;
  - a bad instance name or id, an existing `seed.iso` (left intact), a missing instance
    directory, and the CLI exit status 1 with `REFUSED:` and nothing written;
- a round trip through an independent stdlib reader written from ECMA-119 and the
  Joliet specification:
  - system area zero; descriptor sequence `[(16,1),(17,2),(18,255)]`;
  - volume ids, escape sequence, block size, and volume space size × 2048 = file size;
  - both-endian fields agree; dates as above; path tables hold only the root;
  - the Joliet root holds exactly `.`, `..` and the three files, with byte-exact
    content;
  - the primary names share extents with the Joliet names; no system-use bytes; UTF-8
    with LF only.

**Fixed-input digest.** Name `seed-test`, id

## Observations and inferences

- **Observed:** the pinned QEMU accepts `-object monitor-qmp,id=qmp-monitor,chardev=qmp`,
  serves QMP on it, prints no deprecation warning, and lists the monitor as
  `/objects/qmp-monitor` (`child<monitor-qmp>`).
- **Observed:** WHPX is the enabled accelerator. No `WHPX:` failure.
- **Observed:** `Ignoring request for interrupt vector 0` recurs in a paused boot with
  the new argv and a real seed. **Inference:** the monitor change and the seed are not
  its cause, since it appeared with the old argv and the zero placeholder too. Whether
  it matters to a running guest is unobserved until part b.
- **Observed:** QEMU attached `seed.iso` as a read-only raw virtio disk. **Not
  observed:** whether Debian's cloud-init finds and accepts the volume (label `cidata`,
  Joliet names). That needs a real boot (part b). The spec keeps it UNKNOWN until then.

## Defects

- **`exposed-by-F-03.2.2a`: the user-data template's header comment contains both
  placeholders.** `profiles/seed/user-data.tmpl`, line 4: "The generator substitutes
  {{agent_ssh_public_key}} and the profile's {{scratch_device}}, nothing else." Literal
  substitution, as the spec requires, puts the public key and the device path into
  that YAML comment of the rendered user-data. This was observed in the libarchive
  extraction above. The comment is ignored by cloud-init and holds only non-secret
  values (P5), so the effect is cosmetic. **Carried, not repaired:** the template is
  pinned by sha256 in both `strong-windows-qemu-whpx/profile.json` and
  `strong-incus-vm/profile.json`, and the second is outside this slice's write paths.
  The repair is a template comment without `{{…}}`, re-pinned in both profiles.
- **`introduced-by-F-03.2.2a`, repaired before commit: a `profiles/seed/README.md`
  command block.** Its shell line continuations were lost when the text was spliced in
  by a script. They were restored before commit `0a061e9`.
