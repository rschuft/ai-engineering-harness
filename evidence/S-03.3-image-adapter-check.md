## 1. Why

The pinned SDK launches an ACP provider by its registry's `npx -y --prefer-offline
<package>@<version>` command, rewritten to the bare binary name when that name is found on
`PATH` (recommendation section 1.1, "Command"). The guest denies network egress, so a
missing adapter would leave only the `npx` fallback, which cannot fetch. Decision (e)
asks for the image's actual content, not the Dockerfile's intent.

## 5. Verdict

**R4 holds** for the exact pinned image, for both providers, at the level R4 states:

- **Claude Code:** holds. `/usr/local/bin/claude-agent-acp` is present and byte-identical
  to the Dockerfile's wrapper; it execs `/acp-node/bin/claude-agent-acp`, an npm `bin`
  symlink to the adapter's `dist/index.js`; the adapter is
  `@agentclientprotocol/claude-agent-acp` `0.63.0`, the registry pin. It depends on
  `@anthropic-ai/claude-agent-sdk` `0.3.220`, whose `package.json` declares
  `claudeCodeVersion` `2.1.220`; a platform package `claude-agent-sdk-linux-x64` sits beside
  it.
- **Codex:** holds. `/usr/local/bin/codex-acp` is present and byte-identical to the
  Dockerfile's wrapper; it execs `/acp-node/bin/codex-acp`, a symlink to the adapter's
  `dist/index.js` (1.7 MB); the adapter is `@agentclientprotocol/codex-acp` `2.2.2`, the
  registry pin. Its `package.json` has no `optionalDependencies`; its `node_modules` holds an
  `@openai` scope.
- **Node:** `/acp-node/bin/node` is present (0755, 126,879,696 bytes), with npm `11.21.0`.
  Its sha256 equals the base image's `/usr/local/bin/node`, which the Dockerfile copies from
  `node:24.22.1-trixie-slim`, while the ACP stage downloads `node-v24.22.1`. That is
  consistent with v24.22.1 but was not observed.

Consequences, stated as inference, not observation: with the wrappers in `/usr/local/bin`,
which is on the image's `PATH`, the SDK's `resolve_acp_command` should find each
`binary_name` and run it instead of `npx` (recommendation section 1.1, "Command"). No
derived image is needed **for the adapters**. `npx` is also present (`/usr/local/bin/npx`
and `/acp-node/bin/npx`), so a fallback, if it ever happened, would start and then need the
network the guest denies. The managed settings that allow `Edit`, `Read` and `Bash` (R2)
are in the image as the Dockerfile writes them.
