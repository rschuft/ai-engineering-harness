# E-01.3.1: typed native conversation-create request

- **Date:** 2026-11-10.
- **Plan leaf:** E-01.3.1, "Implement typed native conversation-create request". **Action:**
  build one Agent Server client call with reserved UUID, pinned API version and selected Docker
  runtime; map typed response identifiers. The client enforces the dispatcher route allowlist
  on every call, the decision-0001 `/server_info` preconditions and the resolve, reserve,
  admit, send_create order. **Output:** native conversation creation adapter and
  request/response fixture.
- **Proof (verbatim):** "Request includes authoritative UUID/runtime and captures returned IDs
  without storing duplicate event history. Every dispatcher call, not only the create, is
  checked against the profile's routes.json dispatcher: allowed entries, and a call that is not
  listed is refused before it is sent (the transport is not called). Before a create, the
  /server_info preconditions of decision 0001 are checked (P1 to P5,
  conversation_runtime_routes_v1, idempotent_conversation_create_v1, runtime docker,
  available_conversation_runtimes empty), and a failed precondition refuses the create. The
  call order is resolve, reserve, admit, send_create; send_create receives the reserved record
  re-read from the store; a refused attempt is marked failed. The workspace directory is
  created only after admission and without following links. Every reservation carries workRef
  and outcomeRef. Tests with an injected transport show each rule; a violation of any of them is
  a failure."
- **Authority:** blueprint `#execution-qualification` (dispatch steps 02 and 03, the native
  Agent Server contract) and `#integration-contracts` (the correlation receipt's `workRef`,
  `outcomeRef`, `executionRef`); decision 0001 (s1 the 1.60.1 line, s2 the `/server_info`
  conditions and required configuration); decision 0008 (outcome identity, point 4); decisions
  0009 and 0010 (the managed root's `workspaces` category, store custody); decision 0013 (read
  for boundaries: the management key and the role tokens are not this leaf's); the store's
  lifecycle contract (`integrations/store/README.md`); the E-01.2.2a record section 8 and the
  plan reconciliation rows O-006, O-010, O-013 and O-047.
- **Builds on:** E-01.2.1 and E-01.2.2 slice (a) in `integrations/dispatch/`: `resolve`,
  `ResolvedInputs`, `admit`, `send_create`, `AdmittedCreate`, `workspace_host_path`, 21
  admission refusal codes.
- **Commits:** `6c8630a` (code, tests, fixture, README, `docs/development.md`), `c885bf4`
  (budgets and baseline, separately), and the commit that adds this record.
- **Not claimed:**
  - No live act. No guest, Agent Server, Gitea, network, LLM or host-to-guest connection; no
    `tools/guest.py` invocation; `tests/live_admitted_create.py` was not run. Every transport
    was an injected fake. No transport for live use was added; the management key's custody and
    the per-attempt role tokens are E-01.3.3.
  - The create body is still the F-04.2 disposable template (finding F3 of E-01.2.2a, carried to
    A-01.x and E-03.1); no per-stage or catalog-derived agent, message or tags block.
  - No reconciliation, idempotent retry, event streaming or independent `docker inspect`
    (E-01.4.x, E-01.5).
  - Every store, manifest, profile copy and managed root was in a throwaway directory. Every
    suite ran with `AIEH_DATA_ROOT` set to an empty directory under the session scratch; each of

## 9. Findings

Classified by the fix-forward rule.

- **F1 (introduced-by this leaf; repaired before commit).** The first mutation round left six
  rules unshown (section 6). Four tests were added before `6c8630a`; round 2 killed all 40.
- **F2 (introduced-by this leaf; repaired in `6c8630a`; not verified live).** `send_create` now
  makes two calls (`GET /server_info`, then the create), and `tools/guest.py`'s
  `GuestCreateTransport` refuses a second call. Unadapted, `tests/live_admitted_create.py` would
  have failed. It now passes `/server_info` over the drill's API channel and the create to
  `GuestCreateTransport` (`PreconditionThenCreate`). The helper was parsed but not run: no live
  act was authorized.
- **F3 (exposed-by this leaf; for the Overseer).** Decision 0001 does not define "P1 to P5";
  only the bootstrap log's obligations table and the plan's proof name them. Section 4 gives this
  leaf's numbering, with P1 as the pinned version (decision 0001 s1). The numbering is stricter
  than decision 0001 s2 alone, never weaker. An Overseer confirmation, or a correction, of the
  numbering is invited.
- **F4 (exposed-by this leaf; for the Overseer).** No accepted record fixes where a
  reservation's `outcomeRef` comes from (the lineage README says so too). This leaf takes it from
  the Work's own Backlog.md references: exactly one `outcome:<uuid>[@<commit>]` (decision 0008
  point 4: a change that serves an outcome references it, a Backlog `--ref`). A task that
  reaches its outcome only through a design pointer into the declaring change, with no explicit
  reference, is refused (`OUTCOME_REF_ABSENT`). Consequence: from now on, dispatchable Work must
  carry its outcome reference. Today every request is refused earlier anyway (no approved catalog
  pin, no operational checked-in profile).
- **F5 (a reading made by this leaf, declared).** For the create's answer, a 5xx (and any 2xx
  other than 200 or 201 with the reserved id) is `unknown`, not `failed`. Decision 0001's "any
  non-2xx is a refusal" stops the dispatch either way. `unknown` also keeps the attempt a live
  claim until it is reconciled by its conversation id, so an answer that may have created a
  conversation never allows a second one (store lifecycle contract; blueprint step 05). A 4xx is
  `failed`.
- **F6 (exposed-by; declared).** Precondition refusals call the transport once, for the `GET
  /server_info` itself, and never send the create. "Zero calls" holds for every refusal before
  that read: resolution, re-read, admission, workspace, the allowlist and admission re-checks.
- **F7 (unrelated-but-detected; not changed, out of bounds).** `Taskfile.yml`'s `test` and
  `dispatch:test` descriptions still say "dispatch input resolution and create admission
  tests". This leaf may change the Taskfile only for a new target.
- **Path boundary:** reads stayed in the checkout, the session scratch and the default TEMP
  (the test suites' and profiler's own directories; this session's profile directories were
  removed). The managed root was used only to run its tools interpreter, and every run had
  `AIEH_DATA_ROOT` redirected; the guest-state directory, the Credential Manager and WSL were
  not touched.
