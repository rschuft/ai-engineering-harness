## 2. The design points as implemented

| Decision 0015 (as amended) | Implemented as |
|---|---|
| s1: host-side, `127.0.0.1` only, sole holder of the key | both listeners bind `127.0.0.1` (no address reuse; `SO_EXCLUSIVEADDRUSE` on Windows; no name lookup); the key is held in memory, loaded from the credential provider at start |
| s2.1: entry `AIEH model provider`, user = provider id, written only by an Owner-run command from standard input, `aieh-credential-act/1` receipt with the fingerprint | `credential-set --provider ID`: stdin only (a terminal is refused, `KEY_STDIN_TTY`; no option carries the key), read back, `provision` or `rotate` receipt through F-06.3's `ActReceipt`, trigger `owner direction`; output and messages pass the I7 scan |
| s3.1 + amendment 1 point 1: one random token per attempt bound to conversation, API family, model list, budget (requests, tokens) and expiry; stored hashed; journaled by fingerprint | `aieh-inf-` + 43 random URL-safe characters; only its sha256 digest and its fingerprint are kept; grant receipt `inference/attempt/<attempt id>/grant` (`aieh-inference-grant/1`) written and read back before the token is returned; one grant per attempt, durably (the journal refuses a second, also after a restart) |
| s3.3: revocation immediate, receipt (fingerprint, attempt, trigger, revoker) in the integration store, never the effects store | the grant is marked revoked first (the next request answers 401), then `inference/attempt/<attempt id>/revocation` (`aieh-inference-revocation/1`) with the per-attempt summary; the decision 0007 point 5 triggers only; expiry revokes with trigger `expiry`; an unwritten receipt is retried at each control call |
| s5.1: one upstream origin per family, nowhere else; no cost map, telemetry or update check | `connect_upstream` is the only connector, called only with the admitted token's family upstream; `https` with the system's trust roots, `http` to a loopback IP literal only; no proxy variable is read |
| s5.3 + amendment 1 point 3: declared per-family entries, routed by path, untranslated; route set pinned from observed traffic; no wildcard model; names verified, never assumed | `families.json` with provisional route sets; model allowlists ship empty and admit exact identifiers only; with them empty every issuance is refused (`MODEL_NOT_ALLOWLISTED`) and every inference request answers 401 |
| s6: per-request JSON lines without bodies, headers, token or key; summary receipt at revocation; key fingerprint once at start; I7 scan over every line and receipt | `aieh-inference-audit/1` lines; the start receipt `aieh-inference-broker-start/1` holds the key's fingerprint once; the broker's guard holds the key and every issued token; a failing line is withheld, a failing receipt is not written, a failing answer is replaced |
| Consequences, first bullet: the broker, its config under `components.inference_broker`, the credential set command, tests with a fake provider | as above; the guest, dispatcher, typed-create, seed, profile and contract parts of that bullet are later slices |

**The family declaration format** (`aieh-inference-families/1`): each family has `id`, `status`
(`provisional` or `pinned`), `consumer` (text), `routes` (exact `{method, path}` pairs), `query` (`refuse` or
`pass`), `auth` (`{header, scheme}`, the shape read inbound and written outbound) and `usage` (the extractor).
Shipped: `anthropic-messages` (`POST /v1/messages`, `x-api-key`), `openai-responses` (`POST /v1/responses`,
`Authorization: Bearer`), `openai-chat` (`POST /v1/chat/completions`, `Authorization: Bearer`), all
provisional, all `query: refuse`. `components.inference_broker` carries `control_port`, `inference_port`,
`max_request_bytes`, `max_ttl_s`, `upstream_timeout_s` and per family `provider`, `upstream` (an origin) and
`models`.

## 4. Mutation check of the decision points

Every `raise` replaced by `pass` and every `if`/`elif` test replaced by `False` in `inference_broker.py`,
each mutant run against the suite in its own copy of `integrations/` (session scratch; ten workers; a 60 s
ceiling per mutant). The first pass (253 mutants) left 42 survivors; each was either a missing test (added) or
redundant code (removed: a host check masked by the host-name rule, a read-back scan masked by the read-back
equality check, two in-memory one-grant-per-attempt checks masked by the durable journal check).

Defects introduced by this work and repaired before the commits: a malformed declaration reported as a
refusal (exit 2) instead of a failure (found by the suite); the accounting and the audit line written after
the answer's last byte, so a client's next request could miss them (found by the suite as a race); a refusal
sent before the request body was read, which Windows can reset away when the connection closes (found in
review; small bodies are now drained first); a store that failed to close hiding the start failure and
leaving the audit file open (found by a test added for a mutation survivor).

Final pass at the committed code: **245 mutants, 241 killed, 4 survivors**, each equivalent or not
exercisable in process:

| Line | Mutant | Why it survives |
|---|---|---|
| `_load` | `raise` -> `pass` (re-raise after dropping a half-loaded sibling module) | needs a sibling module that fails to import; not a broker decision |
| `Journal.close` | `if store is not None` -> `False` | `None.close()` raises inside the same best-effort `except`, so the outcome is identical |
| `_Server.server_bind` | `if hasattr(socket, 'SO_EXCLUSIVEADDRUSE')` -> `False` | on this host the default already refuses a second bind of the exact address (WSAEACCES, also with `SO_REUSEADDR`) and admits a wildcard bind in both modes (probed); kept as the documented Windows hardening |
| `__main__` | `if __name__ == '__main__'` -> `False` | the suite calls `main()` in process and launches no process |

## 5. Choices made within the authority (for the Overseer's review)

1. The family declarations (routes, query rule, auth shape, extractor) are a reviewed repository file;
   `config.yml` sets only the ports, limits and, per family, the provider id, the upstream origin and the model
   allowlist. A route change is therefore a reviewed commit, as amendment 1 point 3's pinning implies.
2. No upstream origin is shipped (each is `null` until the Owner sets it), so no provider host is assumed; a
   non-loopback upstream requires a provider id (`CONFIG_PROVIDER_REQUIRED`).
3. Fail closed on unknown usage: after a successful answer that reports no usage (or is cut off), the token
   budget cannot be enforced, so the attempt is refused further requests (`BUDGET_USAGE_UNKNOWN`); an
   upstream error status does not count. Concurrent requests of one attempt can overshoot the token budget by
   their own usage (disclosed).
4. The broker asks the upstream for `Accept-Encoding: identity` so that usage can be read, and strips every
   credential-bearing and forwarding header before adding the family's auth header.
5. A request whose forwarded target, headers or body contain its own token is refused (`TOKEN_IN_REQUEST`).
6. All three families refuse a query string; Claude Code's adapter is expected to send one (`?beta=true` on
   Messages, not verified): the leaf that first runs the family pins it (the declaration admits `query: pass`).
7. The control listener answers only a direct loopback call (`Host` exactly `127.0.0.1:<port>`, no `Origin`,
   `application/json`): a defence against browser-borne requests; it adds no authentication (same-account
   callers stay disclosed, decision 0013 point 6).
8. Conversation and attempt ids are canonical lower-case UUIDs, as the integration store's own ids are.
9. Grants live in memory: a broker stop ends live grants without revocation receipts (its last audit line
   names their fingerprints); one grant per attempt survives restarts through the journal.
10. One credential entry holds one provider's key, so the broker serves one keyed provider at a time; a
    family of another provider id is not ready.
11. One upstream connection per request (no pooling) in this slice.
