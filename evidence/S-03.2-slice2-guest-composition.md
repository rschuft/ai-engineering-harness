## 3. check_profile

An inference endpoint that is not deferred must be `ssh-remote-forward` (never a guestfwd;
`launch.argv` keeps zero guestfwd rules), with an IPv4 address, a port from 1024 to 65535 that
no guest service uses, `guest-to-host` and a forward owner; `active` would need cited evidence.
Its composition is checked in **both states through the generator**: off, the template's drop-in
carries `AllowTcpForwarding no` and no other forwarding directive, its guard installs and
verifies exactly the four declared rules, and the facts are the ordinary ones; on, the overlay
applies, the drop-in is the ordinary one with that line replaced by exactly the declared
directives, the guard (defined, never run, with a stand-in for iptables) installs and verifies
the ACCEPT after the RETURN in iptables only, and the composed `aieh-provision` compiles and
reports `sshd -T`. The declared values must equal the ones derived from the endpoint, the
profile's own `daemon.json` must not carry `bip` or `dns`, and the job sweep's edges must be
private addresses beside the endpoint. A content-addressed compile cache keeps a `check` at
about 7 ms.

|---|---|---|

| provisioning `management API admission` | the four rules in both families | the ACCEPT after the RETURN in iptables, the four in ip6tables |
| provisioning `Moby daemon` | the profile's `daemon.json` | plus `bip` and `dns` |
| egress guard | allowlist empty | allowlist empty |
| P7 `guest forwarding rules` | zero guestfwd | zero guestfwd |
| P5 `provider key fingerprint` | only with `inspect --provider-key-fingerprint` | always; UNKNOWN without one |

The P5 needle: every secret-shaped run (`[A-Za-z0-9_-]{20,512}`, whole) of the guest collection,
`seed.iso`, `launch.json` and `serial.log` is fingerprinted (`sha256:<16 hex>`, the
credential provider's form) and compared; the value is never needed. **From a job**
(`job-access-probe`, an opted-in guest only): the endpoint without a token must answer 401
(`GET /`; the broker checks the token first); `172.17.0.1:8091`, UDP to the endpoint,
`10.0.2.15:8090` and the resolver `172.17.0.1:53` (TCP and UDP) must be refused
(ECONNREFUSED) with the container guard's IPv4 REJECT counters up by at least the refused
attempts; a name lookup must return no address. An edge that answers or a name that resolves is
a stop condition. Tested against fixture output and a fake guest; the existing S-02 catalogue
re-run is the compensating evidence at qualification.

## 10. Not verified, limits and findings

- **Not verified in a guest (planned until the Owner's act and a qualification):** OpenSSH's
  `PermitListen` with `GatewayPorts clientspecified` and the Windows client's `-R` (documented,
  not exercised); the listener's process name (`sshd-session` on OpenSSH 9.8 and later is
  accepted beside `sshd`); `sshd -T` as root at boot; the order in which `iptables -S` prints the
  ACCEPT rule (`-d`, `-i`, `-p`, `-m tcp --dport`, as iptables-save orders them); Moby's `bip`
  and `dns` in this guest and a listener on docker0 across a dockerd restart; the broker's 401
  at `GET /` through the forward; every job-side outcome of section 4.
- **Not done, outside this slice's paths (a decision for the Overseer):** the new credential
  `cred-inference-attempt-token` (directed for the inventory) is **not** committed. The
  inventory checker accepts it, but `check_role_tokens` then fails (COVERAGE: no role is
  granted it; decision 0015's Consequences give `policy/role-tokens.json` the inference-access
  grant to the engineering and reviewer roles) and `check_ci_policy` fails (LANE_MAP_INCOMPLETE:
  `policy/ci-token-secret-policy.json` must assign it a lane). Neither file is in this slice's
  paths. The prepared entry is ready to add with those two.
- **Finding (unrelated-but-detected, not changed):** while a forward session is held, the guest's
  own processes (not only containers) can connect to `172.17.0.1:8090`, which reaches the
  broker's inference listener; admission by attempt token is then the only control.
  `nm-guest-management` (deny, observed) describes SLIRP's `restrict=on` only, and decision 0015
  does not name this path.
- **Limits:** the template's guard comment still says the egress allowlist's "first entry belongs
  to S-03.x, inference" (left so the default bytes stay identical); `recreate` does not carry
  `--inference` (as it does not carry `--egress-falsification`); the provider-key needle finds a
  key only as one whole `[A-Za-z0-9_-]` run of 20 to 512 characters; a job-side scan for the
  provider key is not built (the P5 needle covers the guest as `agent`).
- **Paths beyond the slice's list:** `policy/README.md` (its generated block only, by the
  checker's renderer); `.claude` worker memory only.
- **Process incident:** one mutant in the re-run of the survivors (the manifest left out of
  `create`, with the test's relative instance path resolved in the checkout's directory) created `no-such-instance-dir/ssh/` with a
  throwaway ed25519 key pair in the checkout root; it was untracked, never committed, and
  removed. The test was made hermetic (an absolute path in its own temporary directory,
