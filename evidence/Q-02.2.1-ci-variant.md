## 5. Ruling D: the Python tools set

Declared: the wheel set in the provision lock (by the hash-locked requirements file and its target,
since the per-wheel URLs and sizes need PyPI, which this slice did not read), its role in the upload,
its guest directory and its read-only mount (`/aieh/wheels`, under ruling A's exactness rule). A job
installs with `python -m venv <job dir>` and `pip install --no-index --find-links /aieh/wheels
--require-hashes --only-binary=:all: --no-cache-dir -r tools-requirements.txt` (the bundle's own lock),
so a wheel is admitted only by a hash the lock lists, and nothing persists across jobs. **Carried:** the
workflow side (`HOME` on a writable job directory for the numeric `--user`; the suites run with the
venv's interpreter) is Q-01.x; downloading the wheels for the Linux target (pip's markers must be
evaluated for the target, not the Windows host) is the CI bindings' (`tools/guest.py`).
