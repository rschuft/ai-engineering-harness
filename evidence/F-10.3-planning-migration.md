### The repaired read path

Before (`622bd75`), every object access went through Dulwich again:
- `_raw` read the object (`get_raw`) and checked its content against its id;
- `_object` called `_raw`, then read the object a second time through `object_store[oid]` to
  parse it;
- nothing was kept, so trees walked by several requests were read again, and so were commits
  peeled several times;
- `_parents` read the commit once more through Dulwich's parents provider;
- every read missed Dulwich's packs first (a loose repository), and each miss makes Dulwich
  1.2.21 list `objects/pack` again.

After (`41f0555`), an opened `Repository` keeps a verified-object cache:
- **Keying and verification.** The cache is an LRU dictionary keyed by object id. An object
  enters it only after its content hashed to its id, so the verification of 0014 section 3
  comes before any first use.
- **Bound.** It holds at most `OBJECT_CACHE_BYTES` (32 MiB) of content, the least recently used
  out first. An object larger than an eighth of that is used but not kept, and missing objects
  are never remembered. `close()` empties it.
- **Parsing and parents.** Parsed objects come from the verified bytes (Dulwich's public
  `ShaFile.from_raw_string` with the checked id and the repository's object format), once. A
  commit's parents are taken from the cached commit (`get_parents(sha, commit)`), so grafts and
  shallow boundaries still apply.
- **Unchanged.** The replace-reference refusal still runs before every access, and damage is
  still `GIT_FAILED` naming the object: a damaged object never enters the cache, because the
  check raises first. The interface of section 8 is unchanged.

| The traversal's repository access, one traversal of the example (12 requests) | Before | After |
|---|---|---|
| Dulwich object reads (`get_raw`) | 180 | **17** |
| Module time (median, Git Bash) | 21.1 ms | **4.1 ms** |
| Raw Dulwich (the probe's method), for comparison | 8.7 ms | 9.0 ms |
| Git oracle | 47.8 ms | 48.8 ms |

**The residual pack listing is inside Dulwich.** `PackBasedObjectStore.get_raw` looks in the
packs before the loose objects, and `_lookup_in_packs` rescans the pack directory
(`_update_pack_cache`, an `os.listdir`) once on every miss. No supported Dulwich call reads a
loose object without that step: `contains_loose` gives no content, and `_get_loose_object` is
private. So it remains, once per object the cache does not hold: 17 listings per access, 0.55
ms of the 3.7 ms profiled. Dulwich is not patched.

**The contract suite.** It keeps its 53 ids and outcomes: equal to `c667d0c` with git on
`PATH`, damaged repositories included. With git absent from `PATH`, the recorded half passes
(43 tests) and the oracle half skips with its reason. Without Dulwich it fails: 15 failures
and 88 errors, as at F-10.2. `Integrity.test_damaged_objects` now also asserts:
- no damaged object is cached;
- a second read of a verified object makes no Dulwich read;
- the cache stays within its bound, also when the bound is set to 64 bytes;
- `close()` empties it.
