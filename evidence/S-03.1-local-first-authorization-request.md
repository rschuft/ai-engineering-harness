## 3. The contract stays provider-neutral

The guest-facing inference contract is the **OpenAI-compatible Chat Completions request**
(`POST /v1/chat/completions`, `model`, `messages`), which Ollama serves natively and which most providers
and gateways serve. The conversation's LLM settings carry only `model` (the allowlisted name),
`base_url` (the guest endpoint) and `api_key` (the attempt token). The broker's upstream (Ollama on
loopback, or a cloud provider with its key) is broker configuration behind that contract; the attempt
token, the model and path allowlists, the budgets and the audit name no provider. The cloud alternative
changes the upstream entry and adds A1 and A5; nothing else. (This refines proposed decision 0015's
section 5.3 path allowlist from "the provider's API family" to this one family; recorded on 0015 at S-03.2.)

## 4. The acts (each a separate yes or no)

| # | Act | Exactly what | Effects | Ends |
|---|---|---|---|---|
| **L1** | **Start the Ollama server** (a host act) | `ollama serve` from the existing installation, as the Owner's account, **not the desktop app**, with `OLLAMA_HOST=127.0.0.1:11434` set for that process only; then read `GET /api/version` and `GET /api/tags` | One process listening on `127.0.0.1:11434` only (no LAN); recorded in the host census with its connections | Stopped at teardown; the port checked closed |
| **L2** | **Pull the pinned model** | `gemma4:e2b-it-q4_K_M` (or e4b if chosen) through L1's server, then verify the local manifest sha256 equals the value in section 2; a mismatch removes it and stops the run | Host egress by Ollama to `registry.ollama.ai` and its blob storage, once; about 4.59 GB on disk in the Ollama model store | The model stays for later runs unless the Owner chooses removal at teardown |
| **A2** | **Run the broker** | A host process as the Owner's account; an inference listener and a control listener on `127.0.0.1` (ports declared at S-03.2); upstream exactly `127.0.0.1:11434`; model allowlist exactly the pinned name; path allowlist exactly `POST /v1/chat/completions`; per-attempt token; budget per attempt at most 4 requests and 256 output tokens; audit lines without bodies | Two loopback ports; no egress beyond loopback | Stopped at teardown |
| **A3** | **One guest-to-host path** | The dispatcher's SSH remote forward `172.17.0.1:<port>` in the guest to the broker's inference listener, inside the existing management channel; never to 11434 | The first path from the guest to the host, for this session only; QEMU's command line unchanged | Closed at teardown |
| **A4** | **Guest composition, in one disposable guest created for this run** | sshd: `AllowTcpForwarding remote`, `GatewayPorts clientspecified`, `PermitListen 172.17.0.1:<port>` only; container guard: one accept for that address and port; Moby `bip` pinned; optionally Moby `dns` pointed at the refused gateway address | Two hardening settings relaxed to one address and port; everything else refused and re-tested by the containment catalogue | The guest is destroyed |
| **A6** | **One qualification call** | One conversation, the fixed prompt "Reply with exactly one word: ready", no repository content, at most the A2 budget | A few hundred tokens of local inference; GPU memory for a model of about 4.6 GB while loaded | The token revoked; the conversation ended |

**Order:** L1, L2 (once), broker A2, the guest created with A4, the forward A3, token, create, A6, then
teardown in reverse. **The run is one session**; a failure stops it, with no retry without a new answer.

**Teardown, verified:** the conversation ended and its token revoked (401 at the broker); the forward
closed; the guest destroyed (the instance directory, the process, the listeners); the broker stopped and
its two ports closed; `ollama serve` stopped and `127.0.0.1:11434` closed; the host census back to its
pre-run listeners; firewall rules unchanged (none are touched). The pulled model is kept unless the Owner
answers "remove", in which case it is deleted with `ollama rm` before the server stops.

## 5. What stays unauthorized

Any other model, tag or pull; the installed `gemma4-uncensored` model in any role; the Ollama desktop app;
any Ollama listener off loopback; any guest path other than A3, and any path from a guest to 11434; any
cloud provider, key or internet egress other than L2's registry download; repository content in a
conversation; untrusted workloads; more than one qualification session; any change to Windows, WSL2, the
host firewall or services beyond L1's process; OA-06, OA-07, OA-13.

## 6. What the run establishes, and what it does not

**Establishes**, if every check passes: a conversation in the strong-tier guest reaches a local model only
through the broker under a per-attempt token; the guest holds no credential beyond that token; direct paths
(11434, resolvers, host services, the peer container) stay refused from a job; forward loss fails closed;
teardown leaves no listener behind. **Does not establish:** model quality or suitability for engineering
work; concurrency; the cloud-provider path; the Ollama library's fidelity to Google's weights; Ollama's
behaviour across versions; Linux or macOS hosts.
