`openhands_sdk-1.60.1-py3-none-any.whl` sha256 `f6efa8f8…45eb6b`, `openhands_agent_server-1.60.1-py3-none-any.whl`

### 2.1 Selection, settings and the command

- `ACPAgentSettings` (`sdk/settings/model.py` 1786-2172): `agent_kind: "acp"`, `acp_server` (default
  `claude-code`), `acp_command` (empty = registry default), `acp_args`, `acp_model`, `acp_session_mode`,
  `acp_prompt_timeout` (1800 s), `acp_startup_timeout` (90 s), `mcp_config` (forwarded to the ACP server at
  `session/new`; stdio servers "always forwarded"), `acp_isolate_data_dir` (default false),
  `acp_file_secrets`, `agent_context`. No `tools` field: OpenHands tools are not given to an ACP agent.
- `resolve_acp_command` (2047) and `_prefer_pinned_binary` (2106): a non-empty `acp_command` is used
  verbatim; an empty one takes the registry's `npx -y --prefer-offline <pkg>@<ver>` and rewrites it to the bare
  `binary_name` **only when `shutil.which` finds it**; otherwise the `npx` form stays, and
  `_start_acp_server` first tries to warm the npx cache (`acp_agent.py` 2672, 3110-3125), then spawns `npx`.
  So with `acp_command: []` (the recommendation's section 1.5 item 1) a missing wrapper on the inner server's
  `PATH` becomes an `npx` start that the guest's egress denial makes fail; an explicit `acp_command:
  ["claude-agent-acp"]` never takes the `npx` form (decision D-2, section 6).
- Registry (`sdk/settings/acp_providers.py` 378-425): `claude-code` -> `ANTHROPIC_API_KEY`,
  `ANTHROPIC_BASE_URL`, `default_session_mode` `bypassPermissions`, `data_dir_env_var` `CLAUDE_CONFIG_DIR`,
  `env_conflicts`: `CLAUDE_CODE_OAUTH_TOKEN` strips `ANTHROPIC_API_KEY` and `ANTHROPIC_BASE_URL`; `codex` ->
  `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `agent-full-access`, `CODEX_HOME`, the `CODEX_AUTH_JSON` file secret.

### 2.2 The create and the secrets

- `StartConversationRequest.secrets` is `dict[str, SecretSource]` (`sdk/conversation/request.py` 291): a
  `StaticSecret` (`kind`, `value`) or a **`LookupSecret`** (`url`, `headers`), whose value is fetched by
  `httpx.get(url)` (`sdk/secret/secrets.py` 113-130).
- The Docker-runtime outer server decrypts the request's secrets (`agent_server/launch.py` `request_secrets`
  167) and, before forwarding, **materializes** them (`forward_to_runtime` 228-250, `materialize_secrets`): a
  `LookupSecret` would be fetched **by the outer server**, a management-domain process, from a URL the body
  names. Admission must therefore admit `StaticSecret` only (finding F-2).
- `launch_source` (`launch.py` 137-164): with `agent_settings` (not `agent_profile_id`) the settings are
  validated as sent; the server's stored settings (`server_launch_stores`, 64-79, with its stored
  `mcp_config`) are used only for a profile resolution, which admission refuses (`agent_profile_id` unknown).
  `finalize` (`sdk/launch/finalize.py` 64-110, 162-189) injects managed skills into an ACP agent only when its
  `agent_context` carries skills; with no `agent_context`, none (R11, SOURCE).

### 2.3 The spawn and its environment

`ACPAgent._start_acp_server` (`acp_agent.py` 3051-3260):

- env = the ACP library's `default_environment()`, then **`os.environ` of the inner server** (3077; only npm
  variables stripped, `_strip_inherited_npm_env` 249), then **the whole secret registry** (3089), then the
  per-conversation data dir (`_isolate_acp_data_dir` 2716: `CLAUDE_CONFIG_DIR` =
  `<persistence_dir>/acp/claude-code`), file secrets, `CLAUDECODE` removed, `env_conflicts` applied.
- It does **not** use `sanitized_env` (`sdk/utils/command.py` 17-60), which strips `OH_SECRET_KEY` and
  `OH_SESSION_API_KEYS_*` for the native terminal. So the provider CLI and every process it starts inherit the
  conversation's own session key and cipher key in their environment (finding F-3; the job probe already showed
  both readable by the container's user through `/proc/1/environ`, S-01.3.1/S-01.3.2, so the exposure class is
  the same, its path is new).
- `asyncio.create_subprocess_exec(command, *args, env=env)` (3186): the adapter is a **direct child of the inner
  server process** in the conversation container; stdio pipes carry ACP JSON-RPC.

### 2.4 Delegation: the mechanisms at the pin

| Mechanism | Who starts what | Where it runs | Seen as |
|---|---|---|---|
| (a) The provider's own tools and sub-agents (Claude Code's tools, its sub-agent tool) | The CLI itself: the SDK bridge refuses ACP `fs/*` and `terminal/*` client calls ("ACP server handles terminal operations", `acp_agent.py` 1744-1790), so every command the provider runs is spawned by the provider | Descendants of the adapter, so of the inner server, in the container | Processes under the adapter (slice 1); ACP tool-call events (`sdk/event/acp_tool_call.py`) |
| (b) An ACP session fork (`ask_agent`, `acp_agent.py` 4538-4600: `session/fork`, then a prompt) | The adapter, inside its own process | The adapter process | No new process or conversation is required by the protocol; UNVERIFIED for the pinned adapter |
| (c) OpenHands' children route (`POST /api/conversations/{id}/children`, `agent_server/conversation_router.py` 844-870; `conversation_service.start_child_conversation` 2114-2200: the child **inherits the parent's resolved agent and secrets**) | Whoever holds the conversation's inner key: the native `start_child_conversation` tool (`openhands-tools` `child_conversation/`), which an ACP agent does **not** receive; or any provider process, since the key is in its environment (F-3) | The inner server of the same container (local runtime); for an ACP parent, a second adapter process in the same container | A new conversation on the **inner** server whose `parent_conversation_id` is the parent; no outer-server conversation |
| (d) The OpenHands `start_child_conversation` tool itself | Native (openhands-kind) agents only | as (c) | as (c); A-01.2's gate, not S-03.3's |

What the pinned sources do **not** settle: whether Claude Code 2.1.220's sub-agents run inside the CLI process
or as separate processes, and whether the adapter's fork starts a process. Both are observed live (slice 1's
process tree, slice 5's event reader). Neither (a) nor (b) is assumed to be (c) or (d), and the observation
records which one happened.

## 4. Slices

Each slice is offline unless marked live; each lists what it waits on.

1. **Slice 1 (offline, this dispatch): the containment observation of a conversation container.** A
   standard-library module `integrations/dispatch/conversation_containment.py` that runs (as a file sent to the
   guest) in two vantages and judges on the host: (i) **inside** the conversation container as its user, a
   process inventory (pid, parent, executable, the first argument when it is a path, identity, capabilities,
   `NoNewPrivs`, `Seccomp`, cgroup), the listening sockets with their owner, and the container's cgroup limits;
   (ii) **from the guest root**, every host process in the container's PID namespace with its namespaced pid,
   cgroup and status, beside `docker container inspect`'s PID and limits. Verdicts: the inner server identified
   by its listener; the provider's adapter a direct child of it; every process of the provider's tree a
   descendant of the inner server with PID 1's identity, capabilities, `no_new_privs`, seccomp and cgroup; no
   orphan reparented outside the inner server's tree and no process entered from outside (parent 0); no `npx`
   or `npm` process; the container's limits equal to the admitted caps; the host view's members all in the
   container's cgroup, the provider's processes seen from both vantages; and the before/after sets: no new
   container, no new **outer** conversation, and the **inner** server's new conversations classified by
   `parent_conversation_id` (mechanism (c)) so the evidence distinguishes them from the provider's own
   processes (mechanisms (a), (b)). Waits on nothing; serves S-03.2's child probe too. Placed in
   `integrations/dispatch/` (the conversation the dispatcher created is what it observes) rather than a new
   `integrations/acp/`, whose test suite would run in `task test` only after a `Taskfile.yml` change, which is
   outside this dispatch's paths.
2. **Slice 2 (offline): the qualification create fixture and its admission.** The ACP `agent_settings` block
   (`agent_kind` `acp`, `acp_server` `claude-code`, `acp_command` per D-2, `acp_args` `[]`, `acp_model` the one
   approved identifier read from the broker's configured family allowlist at run time, `acp_session_mode` the
   registry value or null, `acp_isolate_data_dir` true, `mcp_config` `{}`, no `agent_context`, no
   `acp_file_secrets`), `secrets` with exactly the registry's two names as `StaticSecret`s (the attempt token,
   the endpoint URL `http://172.17.0.1:8090`), `secrets_encrypted` false, a `s-03.3-disposable` tag; a pinned
   extract of the registry facts it uses, with the locked wheel's sha256 and the source lines; an admission
   that refuses every other shape (`custom`, a command or argument, another secret name or kind, a non-token
   value, a provider-key-shaped value, MCP, tools, `agent_profile_id`, a profile id) and refuses the fixture for
   a real stage. Waits on D-2, D-3 (and D-6 for the profile contract text).
3. **Slice 3 (offline): route and model discovery without a paid call.** The broker records, for a refused
   request of a grant, the method, path, query parameter **names** and the request's `model` (no values, no
   body), under the I7 scan; a discovery mode of the qualification launcher with the fake upstream; a reader

4. **Slice 4 (offline): the real-key containment search.** A mode of the searcher that receives the real key

5. **Slice 5 (offline): the live qualification driver.** A `tools/guest.py` operation that, on a provisioned

## 6. Decisions to present (not taken here)

- **D-1 Pins for reading the provider's code offline.** The adapter and the CLI are pinned only as image
  content (the image digest; registry pins `@agentclientprotocol/claude-agent-acp@0.63.0`,
  `@anthropic-ai/claude-agent-sdk@0.3.220`, its `claude-agent-sdk-linux-x64` platform package; Codex
  `@agentclientprotocol/codex-acp@2.2.2`); `composition/` pins no npm package of them, so nothing was resolved.
  Options: (a) **preferred**: a second read-only `image-inspect` run of the staged, verified archive for the
  bundled CLI's `package.json`, executable and mode (no new pin; the image is the pin; the staged archive is
  under the guest state directory, outside this dispatch's paths); (b) an npm pin in `composition/` of exactly
  those versions (the exact version as the registry pins it, the lockfile's integrity hashes, installed only
  with `npm ci --ignore-scripts` into a throwaway directory, read as data, never run, no runtime `npx`), which
  is a composition change for the Owner. Needed for: the adapter's fork and sub-agent mechanism (section 2.4
  (b)), the CLI's routes and default secondary model (cross-check for slice 3), its non-inference traffic (R7).
- **D-2 The adapter command in the fixture.** `acp_command: []` (the recommendation) relies on `shutil.which`
  and leaves the `npx` form if the wrapper is not found; `["claude-agent-acp"]` (the registry's `binary_name`,
  exactly) never takes it and fails closed. Either way slice 1 detects an `npx` process. The recommendation's
  text was accepted with the architecture; the explicit form is a hardening proposal for the Architect or the
  Owner, also for A-01.2.
- **D-3 Where the qualification fixture lives and how it is refused for a real stage** (F-1): in the profile
  (`profiles/strong-windows-qemu-whpx/agent-server/`, the F-04.2 pattern, a profile edit) or beside the
  qualification code in `integrations/` (pinned by sha256 there, never read by the dispatcher's admission).
- **D-4 Recording refused routes and models** (F-5): the broker's audit gains method, path, query parameter
  names and the requested `model` for refused requests of a valid grant (no values, no bodies, the I7 scan
  unchanged), plus a fake-upstream discovery run. A change to S-03.2's audit content.
- **D-5 Real-key custody for the search** (F-4): the checker obtains the key from the credential entry the
  broker reads (same account, decision 0013 point 6), holds it in memory, never prints or writes it.
- **D-6 Contract amendments** (Overseer as contract owner, disclosed to the Owner under gate G, recommendation
  section 1.5 item 4): `jobs.environment.secret_names` and the credential-name rule admit exactly the
  provider's key variable (the attempt token); F-3's inherited session and cipher keys in the provider's
  environment disclosed; the P5 needles gain the provider key's fingerprint and the job probe's control the
  token's.
- **Already pending at OA-12** (not new): the exact model identifiers including Claude Code's secondary model;
  the key, its storage, spend caps and budgets; A1 to A6.
