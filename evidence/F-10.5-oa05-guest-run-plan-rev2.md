## 7. Failure handling

**Unchanged from the approved plan.** Justification: every stop and exit path in `main`,
`preconditions`, `build_payload` and `check_report` is byte-identical; only the three constants
they compare against changed.
- **Before create** (checkout, wheels, runner, payload digests, preflight): the script stops; no
  guest exists.
- **create refuses because `f105-linux` exists:** not this run's guest; left untouched; the script
  stops (exit 2). Any other create outcome is followed by destroy.
- **After create, any failure:** that step stops and destroy and the teardown check always run.
- **A failing test** is a result, not a stop: the report is collected, the guest destroyed, the
  verdict DIFFERENT (exit 1).
- **If teardown cannot be verified,** the script prints `task guest:destroy PROFILE=P STATE_DIR=S
  NAME=f105-linux` and exits 2; the Overseer reports it.
- A failed run is not retried under this approval.
