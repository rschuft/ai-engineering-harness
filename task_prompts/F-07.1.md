BOUNDED SCOPE
Define and implement the managed data root and configuration contract: an OS-appropriate external default root (Windows %LOCALAPPDATA%\AIEH\, Linux per XDG), resolved through an established cross-platform path library or the platform conventions, with three top-level lifecycle categories beneath it, persistent/ (durable workspaces, databases, credentials, authorization records, configuration and operational evidence), ephemeral/ (disposable scratch, temporary execution artifacts, caches and regenerable intermediate files) and assets/ (downloaded, reusable, verified artifacts such as pinned model weights, VM base images, installation packages and third-party distributions, each retaining version, provenance, integrity metadata and enough information to reacquire it, deleted only deliberately and reclaimable only when no required consumer depends on it and verified reacquisition is possible), with base images kept distinct from mutable VM disks and overlays, which belong in persistent/ or ephemeral/ by lifecycle; the optional AIEH_DATA_ROOT override, absolute or relative, a relative override resolving against the repository root, never the cwd; a data root inside or containing the source checkout is refused; a tracked example_config.yml and an optional, gitignored config.yml for non-secret settings and per-directory overrides, a relative directory override resolving against the effective root; deterministic precedence of a per-directory override, then AIEH_DATA_ROOT, then the OS default; one shared resolver with thin adapters across language and process boundaries; an evaluation of dotenv as optional convenience only; no secrets in tracked or source-accessible configuration.

REQUIRED OUTPUT
Contract decision, example_config.yml, the shared resolver and its adapters, and tests of the resolution acceptance criteria.

EXACT ACCEPTANCE EVIDENCE
A fresh checkout works without config.yml or .env; default state lives outside the checkout; the root has three top-level lifecycle categories, persistent/ (durable workspaces, databases, credentials, authorization records, configuration and operational evidence), ephemeral/ (disposable scratch, temporary execution artifacts, caches and regenerable intermediate files) and assets/ (downloaded, reusable, verified artifacts such as pinned model weights, VM base images, installation packages and third-party distributions, each retaining version, provenance, integrity metadata and enough information to reacquire it, deleted only deliberately and reclaimable only when no required consumer depends on it and verified reacquisition is possible), with base images kept distinct from mutable VM disks and overlays, which belong in persistent/ or ephemeral/ by lifecycle; the platform defaults follow convention; AIEH_DATA_ROOT relocates the whole root; relative root overrides resolve against the checkout and relative directory overrides against the effective root; absolute overrides work; a data root inside or containing the source checkout is refused; resolution is cwd-independent; invalid configuration fails with actionable errors; no drive-root directories are created.

UPSTREAM CAPABILITY TO REUSE
Established cross-platform path library or platform conventions; a mature lightweight YAML configuration library; dotenv evaluated as optional convenience only.
