EXACT ACCEPTANCE EVIDENCE
The native-resumption determination is recorded from the pinned sources (the Claude Code ACP adapter 0.63.0 and the CLI it bundles, the SDK's ACPAgent and the Agent Server's conversation runtime restart), read offline with no network, each finding cited to its source or stated unknown; D1 uses the new-attempt path below whatever it finds. Offline, with fake upstreams behind the broker and a fake Agent Server: a provider interruption (an authentication, credit, rate-limit or overload refusal passed through from the upstream, or a stream the upstream cut off) and the broker's own stop when its record names no containment, credential or egress cause are each recorded as an interruption. Every broker security refusal (an unknown, revoked or expired token, a refused route, query, model or provider-side reach) and every containment, credential or unexpected-egress stop is recorded as non-retryable. An unknown-token answer after a recorded broker stop of the retryable kind is classified by that stop's record, not as a security refusal. The classification is taken from the broker's audit and per-attempt records, never from an HTTP status alone. When an attempt's conversation ends, or the attempt is stopped, after an interruption, the dispatcher ends the attempt: the conversation's runtime is stopped and observed stopped, the attempt's token is revoked through the control listener (shown by the grant's state), and an end record (attempt, conversation, classification, the broker's codes and upstream statuses, fingerprints only) is written durably in the integration store; the reservation, grant and revocation receipts, the audit and the task's Backlog.md and OpenSpec records are kept unchanged, and the interrupted attempt hands no result to the result path. Ending an interrupted attempt is repeat-safe: repeating it, or resuming it after a crash partway through (after the runtime stopped, after the token was revoked, after the end record was written), converges on one end record, with no second revocation receipt and no duplicate record, shown by tests that repeat each step. A new attempt for the same task (the next ordinal on the same work item, design revision and stage) is admitted only once the earlier attempt's end record shows an interruption and its conversation stopped, and it gets a new conversation and a new token. A provider authentication refusal ends the attempt like any interruption, but a new attempt after one is admitted only once the engineering manager has recorded its cause (for example a key the Owner rotated), never by an automatic retry. A new attempt is refused with a stable code while the earlier attempt has no end record or its conversation still runs, after an authentication refusal whose cause is not recorded, and after a non-retryable end, which stops the leaf as a security stop. No token is granted again to an existing conversation or attempt. No record, report or log carries a token or the provider key.
